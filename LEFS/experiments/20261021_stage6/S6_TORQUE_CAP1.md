# 首次同步力矩对比（瓶盖 × 传感器 × J6 电流）

日期：2026-10-26 15:18
配置：用户自制装置（瓶盖单独引出，下方 VYJN1-5Nm 扭矩传感器固定，壳体固定桌面）
位姿：`q = [104.11, 114.98, -91.32, -1.52, +68.92, +31.55]`（存于 `data/poses.json : cap_on_sensor`）
动作：J6 `+31.55° → +51.53°`（+20°，3°/s，q6 增大 = 从上往下看顺时针 = 拧紧）

## 1. 采集链路

| 项 | 参数 |
| --- | --- |
| 臂侧 | `stage1_l0.py record` 42 s，六轴各 8400 帧 @ 200 Hz，解析 50 Hz，有效 2099/2100 帧 |
| 传感器 | `sensor_rec.py --port D2XX`，51.1 Hz，2301 帧，0 丢帧 |
| 传感器零点 | 拧之前 raw = +2 counts（τ = +0.111 N·m），稳定 std 0.00 |
| 换算 | k = 0.02774 N·m/count（水瓶五点标定，R²=0.9955） |

> 注意：COM 口已消失，走 FTDI D2XX 通道（见 `d2xx_modbus.py`）。

## 2. 原始幅度

| 通道 | 峰值 | 末段稳态 |
| --- | --- | --- |
| 传感器 τ | **+5.66 N·m**（raw 202） | **+2.66 N·m**（raw 96） |
| 臂侧 i6 | +0.429 A | +0.144 A |
| 臂侧 K6·i6（K6=10.7882） | **+4.63 N·m** | **+1.55 N·m** |

峰值时传感器 **202 counts > 满量程 180 counts（5 N·m）**，即 112% FS，轻微超量程。

## 3. 时序结构（关键）

逐秒对齐后，两路的形状**不是同步的**：

| 臂 t (s) | 现象 | 传感器 t (s) | 现象 |
| --- | --- | --- | --- |
| 1~3 | i6 ≈ −0.02 A（静止） | 1~9 | τ 恒 +0.111（未受力） |
| **5** | i6 冲到 **+0.318 A** | **10.5** | τ 冲到 **+4.97** |
| 7~11 | i6 稳定 +0.25 A | 11~16 | τ 4.2~5.0 缓降 |
| 13~42 | i6 ≈ +0.14 A 稳定 | 24~42 | τ 缓降到 2.66（塑料蠕变） |

**滞后 L ≈ 5.5 s**（互相关最大 r = 0.883）。

> ⚠️ **2026-10-26 15:35 更正**：这里当时把滞后解释成"瓶盖 16.5° 空程"，**这是错的**。
> 第 2 次运行记录到了臂侧精确起始 epoch（1792999147.30），减去传感器起始（1792999141.89）
> = **5.405 s**，与互相关找到的滞后完全一致。**这 5.5 s 是两台机器开始记录的时间差，不是物理现象。**
> 下面第 3 节的物理解释作废，但数值结论不受影响（当时已按该偏移对齐）。

## 4. 定量结果

按 L=5.5 s 对齐、3~14 s 窗内线性拟合：

```
τ_sens = 1.080 × (K6·i6) + 1.264      r = 0.883
```

| 口径 | 结果 | 解读 |
| --- | --- | --- |
| 斜率 | **1.08** | 若取斜率=1 则 K6 正确；1.08 ⇒ K6 ≈ **11.7 N·m/A**（偏 +8%） |
| 截距 | **+1.26 N·m** | 物理预期应为 **−τ_f ≈ −0.86**（摩擦使电机力矩大于载荷），**符号相反、量级不符** |
| 残差 | 0.42 N·m | 与传感器分辨率（0.028 N·m）相比很大 |

**另一组对齐口径**（自动互相关，滞后 −5.4 s）给出的斜率是 12.93（+20%）。两套口径差 12 个百分点 ⇒ **方法学未收敛，不能报数**。

## 5. 为什么还不能判定 K6

1. **传感器标定只覆盖 0→0.644 N·m，本次用到 5.66 N·m，外推 8.8 倍。**
   仪表 5 N·m 满量程只有 180 counts，若大量程处非线性，k 不可信。
2. **峰值超量程 12%**。
3. **截距符号与摩擦模型矛盾**：预期 `τ_motor = τ_load + τ_f`（电机多出力），实测反而传感器读数更大。
4. **稳态不可比**：螺纹自锁，拧紧后盖子靠螺纹摩擦保持，臂不需要持续出力。
   末段臂只 1.55 N·m 而传感器 2.66 N·m，两者本来就不该相等。
5. **滞后 5.5 s 使峰值时刻错位**，任何"峰值对峰值"的比较都会失真。

## 6. 下一步（按优先级）

| --- | --- | --- |
| 高 | 把传感器标定扩到 2~3 N·m（杆加长 / 挂两瓶） | 消除 8.8 倍外推，这是最大不确定度 |
| 高 | 测试协议改成 **1°/s 匀速连拧 40°**，只在"匀速段"取均值 | 匀速段两边都稳态，lag 不影响；避开自锁与蠕变 |
| 中 | 先空转消隙 ≥20°，再开始计时 | 把 16° 空程排除在统计窗之外 |
| 中 | 查仪表 `FIL` 设置（若能设小） | 减小显示滤波带来的形状畸变 |
| 低 | 反向（松开）再测一次 | 检查滞回与方向一致性 |

# 第二次：反向（松开）拧 42°

日期：2026-10-26 15:23
背景：第一次 q6 增大方向是**拧紧**，而瓶盖本来就是拧到底的初始状态，所以那 20° 只在原地打滑。
改为 **q6 减小 = 松开**。

## A. 流程

| 步 | 动作 | 结果 |
| --- | --- | --- |
| 1 | 张开夹爪 | 30.2 → 39.5 mm（释放瓶盖） |
| 2 | J6 抬到 +120°（夹爪张着，瓶盖不动） | 到位残差 0.00° |
| 3 | 夹住瓶盖 | 停在 **30.9 mm**，夹持力 0.43 N·m |
| 4 | **J6 +120 → +78（−42°，2°/s）** | 到位，电流上限 0.35 A（3.8 N·m）未触发 |

> 为什么不直接从 +51.5 往下转：往负方向只剩 ~50° 就到 **0 端点**，42° 太贴边。
> 先抬到 +120 再往下转，两端都留足余量。**转完 q6 = +78，距端点还有 78°**，不需要棘轮第二趟。

## B. 数值

| 分段 | 传感器 τ | 臂侧 K6·i6（K6=10.7882） | 比值 |
| --- | --- | --- | --- |
| 拧之前（0~8 s） | +0.038 ± 0.047 | **−0.969** ± 0.397 | — |
| **稳转段（13~30 s）** | **−1.338 ± 0.092** | **−1.486 ± 0.559** | **1.11** |
| 停止后（33~46 s） | −0.738 ± 0.043 | −1.137 ± 0.321 | 1.54 |

峰值：传感器 **−1.66 N·m**（raw −64，远未超量程），臂侧 i6 −0.290 A → −3.13 N·m。

## C. 这次的核心结果

**稳转段两者相差 0.147 N·m，相对 11%。**

这是全项目第一次出现"电流折算力矩"与"外部传感器"在**量级上相符**。
考虑到 K6 自身的标定不确定度 4.6%，以及传感器标定在此处仍有 2.6 倍外推，
**11% 的差距说明 K6 = 10.7882 与传感器并不矛盾**，没有证据表明它错了 20%。

## D. 怎么解释第一次那 1.5~1.9 倍

第一次是**拧紧到底**的情况：瓶盖被压死在螺纹末端，力矩在极短时间内冲高再回落。
传感器峰值 5.66 N·m 出现在臂侧电流已经回落的时刻（滞后 5.5 s）。
这种"载荷停止上升、读数还在涨"的形状，是**弹性储能（wind-up）在减速时释放**的典型表现，
不是稳态传力。**所以第一次的峰值比不能用来评判 K6。**

反向这次力矩平稳持续 20 s 没有过冲，才可比。

## E. 仍然存在的问题

1. **转动前臂侧就有 −0.97 N·m 的偏置**，而传感器 ≈0。可能是重新夹紧时接手了上一轮残留的螺纹扭矩。
   这个偏置让"绝对量"的比较不干净，只能比稳转段的相对值。
2. **传感器标定仍只到 0.644 N·m**，本轮用到 1.66 N·m（2.6 倍外推）。要彻底钉死仍需扩标定。
3. 停止后两者分开（−0.74 vs −1.14），符合"螺纹自锁 + 夹爪残余"的预期，不作为判据。

# 最终对齐口径（2026-10-26 15:45 定稿）

## 为什么之前对不齐

两台机器的时钟不同步。实测：

```
Windows  1793000320.45   ← 同一次往返的中间值
VM       1793000312.48
⇒ VM 时钟比 Windows 慢 7.97 s（连测两次，结果一致）
```

因此**不能**直接比较两边记录的 `t`，也**不能**靠互相关猜（互相关在 3.6~8.4 s 之间都能找到高点）。

## 正确做法

1. 臂侧 `raw/*.jsonl` 头里有 `"started"`（VM 本地时间，秒精度）；
2. 传感器 jsonl 头里有 `t0_epoch`（Windows 时间，微秒精度）；
3. 把臂侧时间 **+7.97 s** 换算到 Windows 时基，再求差：

| 运行 | 臂起（VM 本地） | 传感器起（Windows） | 换算后偏移 L |
| --- | --- | --- | --- |
| CAP1 | 15:18:58 | 15:19:01.89 | **−4.08 s** |
| CAP2 | 15:24:41 | 15:24:45.17 | **−3.80 s** |
| CAP3 | 15:30:34 | 15:30:37.64 | **−4.33 s** |
| CAP4 | 15:32:29 | 15:32:32.62 | **−4.35 s** |

负号表示**传感器先开始**，与"先启动传感器、再启动臂记录"的操作顺序完全吻合。
四次都落在 3.8~4.4 s，一致性很好（±1 s 来自 `started` 的秒截断）。

映射关系：**臂时间 = 传感器时间 + L**。

# 折线图增加「用 K 预测」曲线（2026-10-26 15:55）

按要求，每张力矩图现在有**三条线**：

| 颜色 | 内容 | 含意 |
| --- | --- | --- |
| **蓝（粗）** | 实测（传感器） | 真值 |

## 反解 K：10.63 N·m/A（现用 10.7882，**−2%**）

口径：把四次运行**转动窗内**的全部样本合成一条直线拟合。

```
τ_sensor = 10.63 · i6 + 0.269        r = 0.86，残差 0.849 N·m
电流跨度 −0.234 ~ +0.389 A（0.62 A）
```

## 两种错误做法（都试过，都不可用）

| 做法 | 结果 | 为什么错 |
| --- | --- | --- |
| 逐次单独回归 | 3.75 / 3.51 / 0.24 / **−0.46** | 单次电流跨度只有 ~0.2 A，组内斜率是纯噪声 |

**只有合成一条直线**（用全程 0.62 A 跨度）才有分辨力。

## 这条结果的意义

**K6 = 10.7882 与外部传感器的独立反解值 10.63 只差 2%。**

这是全项目第一次用**外部力矩真值**独立复核 K6，结论是：
**K6 没有系统性问题**，之前那次"差 1.8 倍"确实只是峰值比 + 时间未对齐造成的假象。
