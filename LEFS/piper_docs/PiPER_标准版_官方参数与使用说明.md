## 1. 机型定位与版本确认

PiPER 是一个系列，四个型号共用外观与生态，但臂展、负载、腕部关节行程不同。**先确认你手上是哪一版**，否则后续 URDF、DH 参数、运动学解算都会对不上。

| 型号 | 自由度 | 负载 | 本体重量 | 臂展（工作半径） | 重复定位精度 | J4 行程 | J5 行程 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **PiPER（标准版）** | 6 | **1.5 kg** | **4.2 kg** | **626.75 mm** | ±0.1 mm | -102°~102° | -75°~75° |
| PiPER L | 6 | 1.5 kg | 4.5 kg | 750 mm | ±0.1 mm | -127°~127° | -90°~90° |
| PiPER H | 6 | 2.0 kg | 4.5 kg | 636 mm | ±0.1 mm | -127°~127° | -90°~90° |
| PiPER X | 6 | 1.5 kg | 4.5 kg | 669 mm | ±0.1 mm | -90°~90° | -90°~90° |

**三步确认标准版**：

1. 铭牌 / 包装箱型号为 `PiPER`（不带 L / H / X 后缀）；
2. 本体重量 4.2 kg，臂展 626.75 mm（L 版 750 mm、X 版 669 mm 差异明显）；
3. 读固件版本后再读关节限位：`piper.GetPiperFirmwareVersion()` 与 `0x473` 反馈，实际限位以回读值为准。

> **关节限位有三个版本，必须回读确认**。官方资料里 J4/J6 的行程改过三次：快速上手手册 V1.0（2024.09）写 J4 ±106°、J6 ±100°；用户手册 V1.1.0（2024.12）改为 J4 -102°~102°、J6 ±120°（该版本更新说明明确写了「更新 J6 关节限位设计」）；部分渠道页还写 J4 -100°~112°。**做复现时不要硬编码关节限位**，一律用 `0x472` 查询 / `0x473` 回读的实际值。

## 3. 机械与电气接口

### 3.1 航空插头（7 芯，电源 + CAN 一体）

| 针脚 | 定义 |
| --- | --- |
| 1 | 电源与通讯复合口（航插本体） |
| 2 | 状态指示灯 |
| 3 | J1 & J2 内部连接口（维护用） |
| 4 | 电源正极（24 V） |
| 5 | 电源负极（GND） |
| 6 | CAN_H |
| 7 | CAN_L |

插拔：**红点对红点**，直接插入；拔出时按压带纹理的区域再拉。带纹理区域受力会回缩，属正常结构。

### 3.2 底座安装

- 4 个 M5 螺纹孔，孔距 70 mm × 70 mm，随机附 4 颗 M5 螺钉 + 内六角扳手；
- 官方强调必须固定在刚性表面；**臂展 626 mm 内为危险区**，调试时保持人员清空；
- 移动底盘/升降台安装时按 70 mm 孔距自行设计转接板。

### 3.3 CAN 链路

```
PiPER 航插 CAN_H/CAN_L ──► USB-CAN 模块（官方标配）──► 上位机 USB
```

- 波特率固定 **1 000 000 bps（1 Mbps），不可更改**；
- Linux 下用 `can-utils` 起 `can0`；Windows 下用官方上位机或厂家驱动；
- 官方 SDK 提供 `piper-can find` / `piper-can activate` 自动识别与命名（仅 Linux）。

### 3.4 末端电气接口（XT30 2+2）

末端关节预留 XT30 2+2 接口，供夹爪 / 示教器取电与通信：**24 V，最大 2 A**。

> **官方警告**：末端 CAN 只适配松灵自有设备，**严禁私自接入其他 CAN 设备**，否则可能造成不可控损坏。这也意味着你不能直接把第三方 CAN 力传感器挂到末端总线上——要么走独立总线，要么用非 CAN 接口的传感器。

### 3.5 上电顺序（官方 A–G 步骤）

第一次上电必须按此顺序，跳步可能导致通信异常或使能失败：

1. 插上 A — J2 连接口；
2. 接好 B — 航空插头的 CAN 线；
3. 对插 C — XT30 接头（末端夹爪/示教器供电通信）；
4. 对插 D — 航空插头（红点向下对准凸点）；
5. 插好 E — 适配器插头；
6. 确认 E 的 AC 头已插好并上电，**待电气面板指示灯闪烁绿色**；
7. 把 USB 线插进电脑。

### 3.6 零点与奇异位姿

**零点定义（官方）**：

- J1：零点校准刻度对齐即为零点；
- J2、J3：机械臂**失能后自然垂下**的位置即零点；
- J5：当 **J6 轴线与 J4 共线**时，J5 为零点。

零点位姿坐标：`X = 54.952, Y = 0, Z = 203.386, RX = 0, RY = 85.0, RZ = 0`（单位 mm / 度，基座坐标系）。

**四类奇异位姿**（做轨迹规划时要主动避开，否则逆解退化、关节速度爆表）：

| 类型 | 条件 |
| --- | --- |
| 腕部奇异 | J4 与 J6 共轴 |
| 肘部奇异 | J1 与 J4 共轴 |
| 肩部奇异 | J5 与 J6 的轴交点在 J1 轴线上 |
| 边界奇异 | 末端位于最大工作范围边缘 |

## 5. 首次上电与基本操作流程

按官方顺序执行，**不要跳步**。每一步都有对应状态反馈可以确认。

### 5.1 上电前检查

1. 目视检查本体无变形、线缆无破损；
2. 底座 4 颗 M5 螺钉拧紧，机械臂不会因反力矩倾倒；
3. 航插红点对齐插到位；
4. 电源为 24 V（≤26 V）、≥10 A；
5. 工作半径内无人员、无杂物。

### 5.2 上电与模式选择

1. **上电**：按 3.5 的 A–G 顺序接线，面板指示灯**绿色慢闪**表示主控就绪；
2. **零位姿态**：机械臂需处于零位（J1 刻度对齐、J2/J3 自然下垂、J6 与 J4 共线）后再切换控制模式；
3. **拖动示教模式**（J5 与 J6 之间的按键控制）：
   - 灯**不亮**：示教停止 / 录制结束；
   - 灯**常绿**：进入拖动示教录制；
   - 灯**闪绿（500 ms）**：进入轨迹复现；
   - **单击**：开始 / 停止录制；**双击**：复现上一次轨迹；
   - 每次进入录制会**覆盖**上一条轨迹；**单条轨迹最长 3 分钟**，超时作废。
4. **切换到上位机 / SDK 控制**：必须先把示教灯熄灭（退出示教），在上位机切到**待机模式**，再切到 **CAN 指令控制模式**。反向切换同理，且**必须回到零位**。

### 5.3 上位机软件（ArmRobotUA）

Windows 7 及以上，双击运行，界面功能区：

| 序号 | 功能 |
| --- | --- |
| 1 | 机械臂通讯按钮（连接 / 断开 CAN） |
| 2 | 垂直菜单栏 |
| 3 | 速度百分比设置 |
| 4 | 使能按钮 |
| 5 | 急停按钮 |
| 6 | 窗口缩放 / 关闭 |
| 7 | 操作功能区（关节 / 笛卡尔点动） |
| 8 | 3D 仿真模型 |
| 9 | 轨迹库 |
| 10 | 关节状态数值 |
| 11 | 状态栏（模式、错误码） |

上位机适合：开箱验证、零位校准、快速点动、录简单轨迹。**不适合**做数据采集与策略部署（无时间戳、无批量接口）。

| 路线 | 入口 | 适合场景 | 限制 |
| --- | --- | --- | --- |
| **Python SDK** | `pip3 install piper_sdk` | 数据采集、算法部署、论文复现 | 需自行管理实时性与线程 |
| **ROS 1** | `Piper_ros` 分支 `ros-noetic-no-aloha` | 与既有 ROS1 栈集成、MoveIt | 依赖 Noetic（Ubuntu 20.04） |
| **ROS 2** | 分支 `ros-humble-no-aloha` / `ros-foxy-no-aloha` | 新项目、Isaac Sim / ROS2 生态 | 版本分支需匹配 |
| **上位机 + 离线轨迹** | ArmRobotUA | 快速验证、产线示教 | 不便于编程控制 |

**仿真与模型**：Gazebo / MoveIt 2（`agilex_open_class/piper`）、Isaac Sim（`piper_isaac_sim`）、URDF（`Piper_ros/src/piper_description/urdf`）、官方 CAD（STEP）。

### 6.1 双臂级联与遥操作（官方流程）

要搭主从遥操作或双臂系统，**必须先用上位机分别给两条臂设置主臂 / 从臂模式**（上位机「联动控制区」配置输入输出状态与 ID 偏移值），再把**两个 USB 转 CAN 模块接到同一台电脑**。

- 主臂：`0x470` 设 `0xFA`；从臂：`0x470` 设 `0xFC`；
- 也可用 ID 偏移把两条臂挂在同一条 CAN 总线上（`0x10` / `0x20`），省一个适配器，但两臂数据会在同一接口上交织，解析时需按 ID 分流；
- 遥操作回读注意：从臂在从站模式下才回反馈，主臂进 `0xFA` 后由人拖动。

## 7. SDK 使用说明

### 7.1 环境与安装

```bash
# 依赖：python-can >= 3.3.4；官方测试平台 Ubuntu 18.04 / 20.04 / 22.04，Python 3.6+
pip3 install python-can
pip3 install piper_sdk            # 或 git clone 后 pip3 install .
pip3 show piper_sdk               # 确认版本
```

**版本对应关系（易踩坑）**：

- `piper_sdk 0.0.x`：仅支持 **V1.5-2 之前**的固件；
- 固件 **≥ 1.8-8**：必须用 `C_PiperInterface_V3`（`piper = C_PiperInterface_V3("can0")`）；
- 固件 **S-V1.6-3**：DH 参数变更（J2、J3 坐标系偏移 2°），URDF 需换 `piper_description.urdf`，旧固件用 `piper_description_old.urdf`。

### 7.2 CAN 激活（Linux）

```bash
sudo apt update && sudo apt install can-utils ethtool iproute2
piper-can find                       # 列出 USB-CAN 模块及其 USB 端口
piper-can activate can0 1000000      # 单模块：命名 can0，1 Mbps
# 多模块（如双臂）：用 --usb-port 指定硬件端口绑定名称
piper-can activate can_piper 1000000 --usb-port "3-1.4:1.0"
ifconfig can_piper                   # 确认接口存在
```

也可用仓库自带脚本：`bash can_activate.sh can0 1000000`。

### 7.3 最小可运行示例

```python
import time
from piper_sdk import C_PiperInterface          # 固件 ≥1.8-8 用 C_PiperInterface_V3

piper = C_PiperInterface("can0", judge_flag=False)   # 非官方 CAN 模块时 judge_flag=False
piper.ConnectPort()
time.sleep(0.025)                               # 等首帧，否则固件版本可能返回 -0x4AF
print("firmware:", piper.GetPiperFirmwareVersion())

piper.EnableArm(7)                              # 7 = 六关节 + 夹爪
time.sleep(0.1)

while True:
    js = piper.GetArmJointMsgs()                # 关节角（度）
    hs = piper.GetArmHighSpdInfoMsgs()          # 高速反馈：位置/速度/电流
    print(js, hs)
    time.sleep(0.005)                           # 200 Hz 轮询
```

**必须知道的三个细节**：

1. **反馈首帧是默认值**（角度全 0），必须丢弃第一帧再进入控制循环；
2. **读反馈要求机械臂处于从站模式**；若为主动输出臂（主站），用 `piper.MasterSlaveConfig(0xFC, 0, 0, 0)` 切回；
3. **结束时务必 `DisableArm(7)`**：使能状态会跨进程保持，下次上电若仍使能，任何误发指令都会立即执行。

### 7.4 关键 API 速查

| API | 作用 | 备注 |
| --- | --- | --- |
| `ConnectPort()` | 打开 CAN 收发线程 | 必须先调用 |
| `EnableArm(7)` / `DisableArm(7)` | 使能 / 失能 | 使能后才接受运动指令 |
| `MotionCtrl_2(mode, move_mode, speed, mit, ...)` | 运动模式与速度百分比 | 切模式用 |
| `JointCtrl(j1..j6)` | 关节角控制（度） | 位置-速度模式 |
| `GripperCtrl(stroke, effort, enable, zero)` | 夹爪行程（0.001 mm）与力矩 | 0.001 N·m |
| `MasterSlaveConfig(0xFA/0xFC, ...)` | 主从联动设置 | 0xFA 示教输入臂 / 0xFC 运动输出臂 |
| `GetArmJointMsgs()` | 关节角、状态 | 度 |
| `GetArmEndPoseMsgs()` | 末端位姿 | mm / 度 |
| `GetArmGripperMsgs()` | 夹爪行程与力矩 | 0.001 mm / 0.001 N·m |
| `GetArmHighSpdInfoMsgs()` | **位置 / 速度 / 电流 / effort** | 20 ms 周期，复现关键 |
| `GetArmLowSpdInfoMsgs()` | 电压 / 温度 / 母线电流 / 驱动状态 | 100 ms 周期 |
| `GetMotorStates()` | 电机状态（同上字段） | 便于批量取 |
| `GetPiperFirmwareVersion()` | 固件版本 | 决定用 V2 还是 V3 接口 |

> **MIT 模式警告（官方原文）**：单关节 MIT 协议属于高级功能，**误用会损坏机械臂**。仅在明确知道 `Kp`、`Kd`、`T_ref` 量纲与限幅时使用。

## 8. CAN 协议速查（复现核心）

协议：CAN 2.0B 标准帧，1 Mbps，Motorola（MSB）字节序。ID 分四组：

| ID 段 | 方向 | 用途 |
| --- | --- | --- |
| `0x2A1 ~ 0x2A8` | 臂 → 上位机 | 机械臂主动反馈（状态、位姿、关节角、夹爪） |
| `0x251 ~ 0x256` | 臂 → 上位机 | 关节**高速**反馈（20 ms） |
| `0x261 ~ 0x266` | 臂 → 上位机 | 关节**低速**反馈（100 ms） |
| `0x150 ~ 0x15F` | 上位机 → 臂 | 运动控制指令 |
| `0x470 ~ 0x47E` | 双向 | 参数配置与查询 |

反馈 ID 可整体偏移为 `0x2B1~0x2B8` 或 `0x2C1~0x2C8`，控制 ID 可偏移为 `0x160~0x16F` / `0x170~0x17F` —— **这正是单条 CAN 总线上挂双臂的办法**（见 `0x470`）。

### 8.1 主动反馈

| ID | 内容 |
| --- | --- |
| `0x2A1` | Byte0 控制模式（0x00 待机 / 0x01 CAN 控制 / 0x02 示教 / 0x03 以太网 / 0x04 WiFi / 0x07 离线轨迹）；Byte1 机械臂状态（正常 / 急停 / 无解 / 奇异 / 超限 / 通信异常 / 抱闸 / 碰撞 / 超速…）；Byte2 模式反馈（MOVE P/J/L/C）；Byte3 示教状态；Byte4 运动状态；Byte5 轨迹点号；Byte6-7 故障码位域 |
| `0x2A2` | 末端 X、Y 坐标（int32，0.001 mm） |
| `0x2A3` | 末端 Z（0.001 mm）、RX（0.001°） |
| `0x2A4` | 末端 RY、RZ（0.001°） |
| `0x2A5` | J1、J2 角度（int32，0.001°） |
| `0x2A6` | J3、J4 角度 |
| `0x2A7` | J5、J6 角度 |
| `0x2A8` | 夹爪行程（int32，0.001 mm）、夹爪力矩（int16，0.001 N·m）、状态码 |

### 8.2 关节高速反馈 `0x251 ~ 0x256`（周期 20 ms ≈ 50 Hz）

| 字节 | 含义 | 类型 | 单位 |
| --- | --- | --- | --- |
| byte[0:2] | 转速 | int16 | 0.001 rad/s |
| byte[2:4] | **电机电流** | uint16 | **0.001 A** |
| byte[4:8] | 位置 | int32 | rad |

> **这是复现 FACTR 2 最关键的一帧**：电机电流 `I_m` 就在这里（节点 ID 1~6 对应 J1~J6）。`τ_m = K·I_m`，K 为力矩常数。SDK 的 `GetArmHighSpdInfoMsgs()` 还会额外给出一个 `effort` 字段（按固定系数换算的力矩，0.001 N·m），可直接当 `τ_m` 的初值，但**建议自己按 K 重算并标定**（见复现报告第 7.3 节）。

### 8.3 关节低速反馈 `0x261 ~ 0x266`（周期 100 ms）

| 字节 | 含义 | 单位 |
| --- | --- | --- |
| byte[0:2] | 驱动器电压 | 0.1 V |
| byte[2:4] | 驱动器温度 | 1 ℃ |
| byte[4] | 电机温度 | 1 ℃ |
| byte[5] | 驱动器状态位（电压低 / 电机过温 / 过流 / 驱动过温 / 碰撞保护 / 错误 / 使能 / 堵转） | — |
| byte[6:8] | 母线电流（**1.5 kg 关节电机无采样，默认发 0**） | 0.001 A |

### 8.4 控制指令

| ID | 内容 |
| --- | --- |
| `0x150` | 运动控制指令 1（含拖动示教指令、轨迹索引、离线轨迹包校验） |
| `0x151` | 控制模式 / MOVE 模式（P/J/L/C/M）/ 速度百分比 / **MIT 模式标志（0xAD）** / 安装位置（水平正装、侧装左、侧装右） |
| `0x152 ~ 0x154` | 笛卡尔目标 X/Y/Z/RX/RY/RZ（0.001 mm / 0.001°） |
| `0x155 ~ 0x157` | 关节目标 J1~J6（0.001°） |
| `0x158` | 圆弧模式点位序号（起点/中点/终点） |
| `0x159` | 夹爪行程 + 力矩 + 使能/清错 + 零点设置 |
| `0x15A ~ 0x15F` | J1~J6 单关节 **MIT 控制**（Pos_ref / Vel_ref / Kp / Kd / T_ref），官方参考 `Kp=10`、`Kd=0.8` |

### 8.5 配置与查询

| ID | 内容 |

## 9. 反馈频率与实时性预算

| 数据 | 帧 | 周期 | 可用频率 |
| --- | --- | --- | --- |
| 关节位置 / 速度 / **电流** | `0x251~0x256` | 20 ms | **50 Hz** |
| 关节角（度）、末端位姿、夹爪 | `0x2A1~0x2A8` | 由主控轮询，SDK 日志中带 `Hz` 字段 | 实测常为 100~200 Hz |
| 电压 / 温度 / 母线电流 | `0x261~0x266` | 100 ms | 10 Hz |

**工程结论**：

- 训练/推理用 100 Hz 时，电流只有 50 Hz 采样 → 必须**零阶保持或线性插值**，并在文档里写明插值方式，否则 `τ_m` 序列会有阶梯伪影；
- 更稳妥的做法：**整套管线直接跑 50 Hz**，与电流原生频率对齐，再把论文的 `H=50`（约 0.5 秒历史 @100 Hz）换算成 `H=25`（约 0.5 秒 @50 Hz）；
- 控制指令下发建议 ≤ 100 Hz，位置-速度模式下指令间隔过短会被主控平滑，反而引入跟踪滞后。

## 10. 安全、边界与常见坑

### 10.1 硬边界（官方）

- 负载 **≤ 1.5 kg**（含末端工具）；
- 供电 **24 V，绝不超过 26 V，电流 ≥ 10 A**；
- 工作温度 -20~50 ℃，湿度 25%~85% 非冷凝，**IP22**（不防水不防尘，远离切削液、粉尘）；
- 拖动示教单条轨迹 **≤ 3 分钟**；
- 本体工作时不带碰撞检测传感器（**无自动避障**），必须靠人/软件保护；
- 运行中本体发热，停机后需冷却约 1 小时再触碰；
- 强磁场会损坏本体，远离电磁铁、大功率电机。

### 10.2 碰撞保护、维护与紧急处理

**碰撞保护**：上位机「碰撞等级」区可对 6 个关节分别设置 **等级 1 ~ 等级 8**（操作流程：编辑 → 保存）。等级越高越灵敏/越保守（以官方上位机说明为准）。做数据采集或力估计实验时，**固定等级并写入实验记录**——等级变化会改变力矩行为，导致 `τ_f` 分布漂移。

**维护与保养（官方）**：

- 存放：使用完毕**复位零点后断电**，线束收纳，避免缠绕与大力牵拉；环境 -20~50 ℃、湿度 25%~85% 非冷凝。
- 保养（必须在零点、断电状态下进行）：湿巾/干布清理灰尘油渍；检查螺丝是否松动；检查电机与结构件有无破损变形；检查电源线与 CAN 线是否稳固、表皮是否破损。

**紧急处理**：

- **断电**：紧急情况可直接拔航插断电。注意断电后机械臂**立即失能并自由掉落**，需防止砸伤人或损坏设备；官方明确「拔线是应急手段，不用于防止伤害」。
- **急停**：连接上位机时，可用上位机暂停按钮暂停/恢复动作。

### 10.3 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `GetPiperFirmwareVersion()` 返回 `-0x4AF` | 读得太早，反馈帧未到 | `ConnectPort()` 后 `sleep(0.025+)` 再读 |
| 使能后不动 | 未切到 CAN 指令控制模式 / 仍在示教模式 | 示教灯熄灭 → 上位机待机 → CAN 模式，且**先回零位** |
| 关节角全 0 | 读到首帧默认值 / 机械臂在主站模式 | 丢弃首帧；用 `MasterSlaveConfig(0xFC,0,0,0)` 切从站 |
| `SendCanMessage(100017)` | CAN 模块未激活或掉线 | `ip link` 检查、重插、重启上位机 |
| 双臂只有一台响应 | 两台 ID 冲突 | 用 `0x470` 给一台设 0x10 / 0x20 偏移 |
| 停顿后再启动仍使能 | 使能状态跨进程保持 | 退出前 `DisableArm(7)` |
| 运动学对不上 URDF | 固件 ≥ S-V1.6-3 DH 变了（J2/J3 偏移 2°） | 换新 URDF，或 SDK 里 `dh_is_offset=1` |
| 电流数据跳变/为 0 | 用了低速帧的母线电流（1.5 kg 机型无采样） | 改用高速帧 `0x251` 的 `电流` 字段 |
