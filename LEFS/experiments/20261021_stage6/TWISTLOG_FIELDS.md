# 全量数据字段速查（twistlog，32 列）

> 适用：`1.全量原盖未打开`、`2.全量预松未全开`、`3.棘轮全量圆盖三圈开_轮1~3`、
>   
> `4.棘轮全量预开全打开_轮1~3`、`5.全量预松1_未打开`、`5.全量预松2_打开`、
>   
> `5.全量预松3_已打开空转` —— 共 11 个文件，格式完全一致。
>   
> 生成脚本：`twist_log.py`。记录率：实测 **171~173 Hz**（目标 200，受 3 次 SDK 读取耗时限制）。

## 6. 夹爪（J7）

| #  | 列             | 含义     | 单位               | 来源                                    | 实测范围               |
| -- | ------------- | ------ | ---------------- | ------------------------------------- | ------------------ |
| 21 | `grip_ang_mm` | 两指开度   | **mm**           | `0x2A8` 的 `grippers_angle`，0.001 mm   | 29.6 ~ 29.9（夹住瓶盖时） |
| 22 | `grip_eff_nm` | 夹爪力矩反馈 | **N·m，负 = 夹紧方向** | `0x2A8` 的 `grippers_effort`，0.001 N·m | −0.40 ~ −0.56      |

### ⚠️ 夹爪**没有电流反馈**

我查了 SDK 的 `GetArmGripperMsgs().gripper_state`，全部字段只有三个：

```
grippers_angle     开度，0.001 mm
grippers_effort    力矩，0.001 N·m
foc_status         FOC 驱动状态位（8 个 bool）
                   其中含 driver_overcurrent（过流标志），但**不给电流数值**
```

**所以拿不到"J7 电流"。** 能拿到的是**力矩** `grip_eff_nm`，它比电流更直接
  
（省掉了"电流→力矩"那一步 K 换算），物理意义也更明确。

夹爪是 FOC 驱动，驱动器内部有过流保护，但只对外暴露"是否过流"这一位，不暴露电流值。

**如果将来一定要电流**，只能自己标定夹爪的力矩常数 `K7`（`I7 = effort / K7`），
  
而 `I7` 本身也读不到——所以这条路走不通。**用 effort 就是终点了。**

## 9. 换算速查

```
J6 力矩        τ = |i6| × 10.7882 − 0.86        (N·m)
J6 电流→原始   raw = i6 × 1000                   (0.001 A)
夹爪原始       angle_raw = grip_ang_mm × 1000    (0.001 mm)
              effort_raw = grip_eff_nm × 1000   (0.001 N·m)
跟踪滞后       lag = qcmd6 − q6                   (°)，正常 0.5~1.0
真实拧盖时长   T = t_s[-1] − 1.0                  (s)
```

## 10. 读数据的三条纪律

1. **`i2` 的 −1.77 A 是重力前馈**，不是负载。别看它大就以为在受力。
2. **夹爪只有 effort，没有电流。** 别去找 `i7`，不存在。
3. **`slip` / `bite_ratio` 不是判据**，只是趋势。要判"拧开"只能二值法（转够圈数后上提）。

## 11. 精度与误差（实测，8 份全量数据统计）

### 11.1 先分清三个概念

| 概念             | 电流               | 夹爪 effort     | 说明                   |
| -------------- | ---------------- | ------------- | -------------------- |
| **分辨率**（能表示多细） | **0.001 A**      | **0.001 N·m** | 已验证：所有值都是 0.001 的整数倍 |
| **量程**         | ±32.767 A（int16） | 未标称           | `int16 × 0.001`      |
| **精度**（离真值多远）  | **厂家不公布**        | **厂家不公布**     | 只能实测                 |

**分辨率 ≠ 精度，这里差 20~80 倍。**

### 11.2 实测噪声（J1~J5 拧盖时不动，其波动即纯噪声）

| 轴  | 均值 (A) | 单帧 std | **差分 std**（白噪声） | **慢漂 std** | 峰峰    |
| -- | ------ | ------ | --------------- | ---------- | ----- |
| J1 | +0.055 | 0.0184 | 0.0073          | 0.0145     | 0.205 |
| J2 | −1.667 | 0.0792 | **0.0031**      | 0.0785     | 0.668 |
| J3 | −0.676 | 0.0455 | 0.0037          | 0.0442     | 0.377 |
| J4 | +0.106 | 0.0452 | 0.0095          | 0.0421     | 0.486 |
| J5 | +0.133 | 0.0778 | 0.0053          | 0.0752     | 0.683 |

**两个关键结论**：

1. **白噪声只有 0.003~0.010 A**（差分法），但**慢漂是 0.014~0.079 A**——**噪声 90% 是低频漂移**。
2. 所以**滑动平均基本无效**：慢漂 std 几乎等于单帧 std（J2：0.0785 vs 0.0792）。

漂移来源：J6 转动带动整臂振动 + 温漂 + 固件重力前馈随姿态微变。
  
**不同姿态的噪声不能互相引用**（台面标定姿态曾测到 0.016 A 量级，这里是 0.08）。

### 11.3 系统误差：零点偏置

J1 轴与重力平行，**重力矩恒为 0**，所以它的读数就是零偏：

```
i1 均值 = +0.0776 A   (std 0.0144)
折合 K1=1.18 时 → +0.092 N·m 的虚假力矩
```

而且**零偏会随实验漂移**（8 份数据里 i1 均值在 0.05~0.08 A 之间）。

⇒ 所以**必须用差分**（`I_带载 − I_空载`），不能看绝对值。这也是 K 标定必须差分的原因。

### 11.4 传导到力矩

`τ = K · I`，误差有两个来源：

| 来源                | J2/J3                  | J4/J5               | J6                     |
| ----------------- | ---------------------- | ------------------- | ---------------------- |
| **K 的误差**（标定）     | 11.8%                  | 79.6%               | **4.6%**               |
| **I 的误差**（±1σ 漂移） | 0.079 A → **0.37 N·m** | 0.078 A → 0.058 N·m | 0.079 A → **0.85 N·m** |

J2 最糟：噪声 0.079 A × K 4.72 = **0.37 N·m**，与 L1 实测的 J2 OOF 0.305 N·m 同量级
  
——**说明 L1 的误差已经被电流噪声地板限制住了**，不是模型不行。

### 11.5 夹爪 effort 的精度

| 量             | 均值     | 单帧 std | 差分 std     |
| ------------- | ------ | ------ | ---------- |
| `grip_eff_nm` | −0.437 | 0.0115 | **0.0033** |
| `grip_ang_mm` | 29.775 | 0.0144 | **0.0003** |

注意：**开度几乎不动（差分 0.0003 mm），但 effort 差分有 0.0033 N·m**。
  
所以 effort 的波动**不是夹爪在动，是真实的力矩变化**（夹持力随瓶盖表面起伏）。
  
⇒ effort 的 std 不能当"测量噪声"看，它混了真实物理量。

### 11.6 实用结论：别看小数点后三位

```
i6 = −0.1899   ← 有效信息只有 −0.19 ± 0.08
```

分辨率 1 mA 给人"能读到千分之一安"的错觉，但漂移是 20~80 mA。
  
**报告里写电流保留 2 位小数（0.19 A）就够了，第 3 位是噪声。**

`effort` 同理：`−0.448` 里的 `8` 有意义（分辨率 1 mN·m、噪声 3 mN·m），
  
但 `−0.4480` 最后那个 `0` 没有。

## 12. 为什么 I6 区分不了"拧动了"和"没拧动"

以最直接的一组对照为例：`3.…_轮1`（瓶盖**未开**）vs `4.…_轮1`（瓶盖**动了**）。

### 12.1 数据上确实分不开

| 指标              | 3-未开                  | 4-动了                  | 差            |
| --------------- | --------------------- | --------------------- | ------------ |
| I6 均值           | 0.1808                | 0.1705                | **0.0103 A** |
| P10 / P50 / P90 | 0.088 / 0.171 / 0.292 | 0.068 / 0.163 / 0.283 | <0.01        |
| P99 / 最大        | 0.380 / 0.432         | 0.373 / 0.443         | ~0.01        |
| 1 s 滑均 std      | 0.0187                | 0.0218                | —            |
| q6 跟踪误差 lead    | 0.631°                | 0.624°                | **0.007°**   |
| 与 i1~i5 的相关     | ≤0.15                 | ≤0.18                 | 都极弱          |

**每一个分位数都差不到 0.01 A，而单帧噪声是 0.08 A——信号比噪声小 8 倍。**

### 12.2 为什么物理上就该分不开

`I6` 测的是 **"J6 用了多大力"，不是 "瓶盖转了多少"**。

J6 转动时遇到的阻力 = 减速箱摩擦（0.86 N·m）+ 夹爪与瓶盖的摩擦传递，
  
而摩擦传递有个上限 `τ_max = 2μFr`（实测约 1.0~1.5 N·m）。

- **瓶盖未开**：夹爪在瓶盖圆柱面上打滑，J6 输出到 `τ_max` 就滑
- **瓶盖转了**：夹爪带着盖转，J6 输出要克服螺纹阻力，但**同样受 `τ_max` 钳制**

⇒ **两种情况 J6 都在同一个饱和点附近出力，电流自然一样。**
  
瓶颈是夹爪与瓶盖之间的摩擦，不是 J6 的能力，所以 I6 里不含"瓶盖状态"这个信息。

### 12.3 粘滑把剩余信息也埋了

I6 在 0.00~0.44 A 之间每秒跳一次（峰峰 0.44 A），是两者均值差（0.01 A）的 **40 倍**。

而且自相关分析显示：滞后 1 帧 ρ=0.31，到 1 s（176 帧）又回升到 0.06~0.14（粘滑周期）。
  
**2300 帧的有效独立样本只有约 183 个**（不是 2300）。

所以均值差的统计量：

```
SE ≈ 0.08 / √183 ≈ 0.0059 A
t  ≈ 0.0103 / 0.0059 ≈ 1.75   （边缘，p≈0.08）
```

### 12.4 信息其实在"跨轮趋势"里

| 组       | 轮1    | 轮2        | 轮3        | 解读                             |
| ------- | ----- | --------- | --------- | ------------------------------ |
| 3（三圈才开） | 0.181 | 0.193     | 0.177     | **不变** → 三轮都卡在同一饱和点，盖一直没松到位    |
| 4（预开后）  | 0.171 | **0.124** | **0.122** | **降 27%** → 轮1 就开了，轮2/3 夹着松盖空转 |

**结论**：

- ✅ I6 **能**反映"盖子是否已经脱离"（变化 >20%，且伴随空转率从 60% 升到 83%）
- ❌ I6 **不能**反映"这一轮有没有拧动"（变化 <6%，淹没在噪声里）

### 12.5 要判"这一轮转没转"，只能独立测转角

电流这条路物理上已经到头了。可行方案：

1. **瓶盖贴标记 + 相机**（最直接，每轮前后各拍一张，量转角）
2. **瓶身画角度刻度 + 定时拍照**（低成本替代）
3. **二值法**：转够圈数后上提，看能否带走瓶盖（判"最终开没开"，不判"转了多少"）

**别再在电流上找判据了**——三个口径（突降、末段比值、逐轮均值）今天全部被推翻，
  
原因就是这一节讲的：I6 里没有那个信息。

## 13. 判"打滑 vs 跟着转"：现有信号全部排除（实测）

对 `3.…_轮1`（未开）与 `4.…_轮1`（动了）逐个测了 6 类信号：

| # | 候选信号                   | 未开                   | 动了                   | 判据成立？                     |
| - | ---------------------- | -------------------- | -------------------- | ------------------------- |
| 1 | **I6** 电流（均值/分位/滑均）    | 0.1808               | 0.1705               | ❌ 差 0.01 A，噪声 0.08（见 §12） |
| 2 | **夹爪开度** `grip_ang_mm` | 29.890（min=max）      | 29.610（min=max）      | ❌ **峰峰 0.000 µm，完全恒定**    |
| 3 | **dq6** 角速度            | −13.705 / std 8.120  | −13.704 / std 8.171  | ❌ 均值差 0.001 °/s           |
| 4 | **夹爪 effort**          | −0.4385 / std 0.0035 | −0.4436 / std 0.0034 | ❌ 差 1.2%，小于噪声             |
| 5 | **q6 跟踪误差**（含高频分量）     | −0.631 / 高频 0.1186   | −0.624 / 高频 0.1206   | ❌ 差 0.007°                |
| 6 | **粘滑峰间隔**              | 7.4 帧（std 4.4）       | 7.9 帧（std 6.0）       | ❌ 差 7%，std 更大             |

### 为什么全都无效

**根本原因：这是一套"位置控制 + 摩擦饱和"的系统，两类信息分别被两条通道吃掉了。**

```
力信息  →  被摩擦上限钳制（τ_max = 2μFr），J6 无论转不转都顶在同一饱和点
位置信息 → 被位置闭环补偿（J6 和夹爪都是位置控制，负载差异被吃掉）
```

- **J6**：位置环输出足够扭矩让 q6 跟上指令，所以 q6/lead/dq6 都看不出负载
- **夹爪**：位置控制，闭合后开度反馈**完全冻结**（min=max，峰峰 0 µm），连瓶盖圆度导致的微动都看不到

所以**不是"信号弱"，是这两条通道里本来就没有这个信息**。

### 唯一可行的两条路

**A. 外部测转角（推荐）**

1. 瓶盖侧面贴一条细标记（或涂一道漆），每轮前后各拍一张
2. 瓶身画 0/90/180/270 刻度，人眼或相机读
3. 需要相机；没有就退化成"人眼每轮看一眼"

**B. 二值上提法（不需要额外硬件）**

每轮结束后：张开夹爪 → J6 不动 → 沿 +Z 抬 5 mm → 再夹 → 提起 20 mm

- 瓶盖被带走 = 已经松脱
- 带不走 = 还咬在螺纹上

这只回答"是否已开"，不回答"转了多少"，但**足够做流程控制**。

### 不要走的弯路

- ❌ 换更灵敏的统计量（分位数、滑均、差分、自相关、峰间隔）——都试过了
- ❌ 加长采样时间——有效样本数受粘滑周期限制，2300 帧只有 183 个独立样本
- ❌ 用 MIT 模式给恒力矩——两者阻力都是 τ_max，纯力矩下依然分不开

## 14. 六类信号的方差与"为什么全都不可信"

对照：`3.…_轮1`（瓶盖未开，n=2299）vs `4.…_轮1`（瓶盖动了，n=2304）。
有效独立样本 **n_eff ≈ 183**（由自相关估得，见 §12.3）。

| 6 | 夹爪开度 | 0.280 mm | **0** | **0** | 0 | ∞ | — | ❌ 退化 |

\* 表观 t 一律按 n_eff=183 计算，即"最有利的算法"。即便如此也只有两个"显著"，
而这两个恰好都是假的（见下）。

### 14.2 五条不可信的原因

**① 实验设计不是配对对照（根本问题）**

两次实验的初始条件全不同：初始扭矩（一颗拧紧、一颗预开）、夹紧位置（29.89 vs 29.61 mm）、
瓶盖已被拧过的次数。**没有配对，任何"显著性"都不能归因到"瓶盖是否转动"。**

**② 有效样本不是 2300，是 183**

粘滑让相邻帧强相关（lag1 ρ=0.31，1 s 后回升 0.06~0.14）。
`n_eff = n/(1+2Σρ) ≈ 183`。**用 2300 算标准误会把 SE 低估 3.5 倍。**

**③ 夹爪 effort 的"显著"是混杂（第 4 行）**

```
3-轮1:  开度 29.890 mm → effort −0.4385
4-轮1:  开度 29.610 mm → effort −0.4436
```

4-轮1 多夹合了 **0.28 mm**，夹持力天然更大。
而且 effort 几乎恒定（σ=0.0035，仅 0.8%），所以夹紧程度的一丁点差异都会"显著"。
⇒ **d=1.49、t=20.2 全是夹紧程度的功劳，与瓶盖状态无关。**

**④ I6 滑均的"显著"是平滑制造的（第 2 行）**

滑均把 σ 从 0.0793 压到 0.0203（降 74%），但**有效样本同时从 183 掉到约 13**
（窗口 1 s，13 s 数据只剩 13 个独立点）。

| 算法 | σ | n_eff | SE | t |
|---|---|---|---|---|
| 原始 | 0.0793 | 183 | 0.00587 | 1.75 |
| 滑均 + **错配** n=183 | 0.0203 | 183 | 0.00150 | **6.79** ❌ |
| 滑均 + **正确** n=13 | 0.0203 | 13 | 0.00564 | **1.81** |

**平滑后的 σ 必须配平滑后的 n**。修正后 t=1.81，仍是边缘。

**⑤ 夹爪开度退化（第 6 行）**

σ²=0（每次内部完全恒定，反馈冻结），d=∞。
但这只是"两次夹到不同位置"（29.89 vs 29.61），不是判别信息。
**方差为 0 时效应量无定义，不能用。**

### 14.3 结论

| 判定 | 信号 |
|---|---|
| 真·无信号（d<0.15） | dq6、q6 lead、粘滑峰间隔、I6 原始 |
| 假显著·混杂 | 夹爪 effort（夹紧位置不同） |
| 假显著·平滑陷阱 | I6 1s 滑均 |
| 退化不可算 | 夹爪开度（σ²=0） |
| **可信的** | **无** |

**一个都没有。** 这与 §12、§13 的物理结论一致：
力被摩擦上限钳死、位置被闭环吃掉，信息不在这些通道里。

### 14.4 如果非要再做统计检验，最少要满足

1. **配对设计**：同一颗盖，交替"拧紧 1 圈 / 松开 1 圈"，各做 5 次
2. **固定夹紧位置**：每次夹到同一开度（瓶盖有直径公差，现有硬件做不到）
3. **用 n_eff 而非 n**，且平滑时必须同步缩样本数
4. **多信号联合**（单信号 d<0.2 时，联合也救不回来——先做功效分析再开跑）

第 2 条做不到，所以这条路到此为止。

## 15. effort 能不能判"打滑"？——不能，但它能判"夹持质量"

### 15.1 现象确实存在

`1.全量原盖未打开` vs `4.…_轮2`（这轮盖开了）：

| | 开度 | \|eff\| 均值 | std | I6 均值 | 空转% |
|---|---|---|---|---|---|
| 1-未打开 | 29.890 mm | 0.4437 | 0.0068 | 0.1899 | 58% |
| **4-轮2** | 29.820 mm | **0.4584** | 0.0067 | 0.1240 | 83% |

**4-轮2 的 effort 确实高 0.0147（+3.3%）**。观察成立。

### 15.2 但它不随打滑变化（决定性证据）

把每帧按 I6 分档，看 effort 在"空转"与"顶住"时是否不同：

| 文件 | 空转 I6<0.05 | 低 0.05~0.15 | 中 0.15~0.25 | 顶住 I6>0.25 | 极差 |
|---|---|---|---|---|---|
| 1-未打开 | 0.4423 (24帧) | 0.4428 | 0.4446 | 0.4435 | **0.0023** |
| 3-轮1 | 0.4365 (35) | 0.4381 | 0.4387 | 0.4389 | **0.0024** |
| 4-轮2 | 0.4582 (462) | 0.4578 | 0.4595 | 0.4594 | **0.0017** |

**三个文件里，空转与顶住的 effort 差都 <0.003，而 std 是 0.003~0.007。**
⇒ **effort 对"此刻是否在滑"完全不响应。**

### 15.3 那 0.0147 的差异来自哪里？——夹紧位置

| 开度 | 文件 | \|eff\| | 结果 |
|---|---|---|---|
| 29.890 | 1 | 0.4437 | 未开 |
| 29.890 | 3-轮1 | 0.4385 | 未开 |
| 29.820 | 3-轮2 | **0.4608** | 开 |
| 29.820 | 4-轮2 | **0.4584** | 开 |

**同开度的两次 effort 几乎相同**（0.4437/0.4385、0.4608/0.4584），
跨开度才出现差异。⇒ **effort 主要由"这次夹得多紧"决定，不是"是否打滑"。**

4-轮2 比 1 多夹合了 0.07 mm（29.820 vs 29.890），所以 effort 高。这是**混杂**，不是因果。

### 15.4 但 effort 仍有价值：它是"原因侧"的指标

```
effort（夹持力） → τ_max = 2μFr → 能传多大扭矩 → 会不会开
I6（传递扭矩）   → 已经传了多少 → 看不出将不将开
```

**effort 在因果链的上游，I6 在下游。** 我一直在看下游，这个方向本来就难。

所以 effort 的用法应该是：

| 用途 | 能不能 |
|---|---|
| 跨次比较"这次夹得好不好" | ✅ **能**（effort 高 = 夹得紧 = 传递上限高） |
| 过程内检测"此刻在滑吗" | ❌ **不能**（档间差 0.002，噪声 0.005） |
| 预测"这次会不会开" | ⚠️ 弱相关（同开度下与结果无干净对应） |

### 15.5 ~~意外发现~~ 已验证：effort 骤降 + 开度坍缩 = "盖已脱离夹爪"

`4.…_轮3`（瓶盖彻底松开那轮）当时是唯一正样本：

**均值低 15%、波动大 3~17 倍。** 当时结论是「只有 1 个样本，不能当判据，要再采几次」。

### 15.5b 新发现：比 effort 更硬的是「夹爪开度坍缩」

`grip_ang_mm` 是**几何量**，不掺电机噪声，物理意义直接：

- 盖一直被两指夹着 → 夹的直径不变 → 开度是一条水平直线
- 盖滑出夹爪 → 两指合拢 → 开度阶梯式下跳 0.21~0.35 mm

8 份未脱开的记录开度首末差**精确为 0.000 mm**（不是"小"，是真的没动），
3 份脱开的全部 ≥0.21 mm。**这个信号比 effort 干净得多，应作为主判据。**

⚠️ **判据边界（必须说清楚）**：开度坍缩证明的是「盖离开夹爪」，
**不能证明「螺纹已脱开」**。反例就是组3 轮3 —— 盖明明拧开了，
但还卡在两指之间，开度 29.82 全程没动。

所以正确用法：
- **开度坍缩** → 盖已自由、可以取走
- **开度不变** → 盖仍在爪内，螺纹脱没脱**数据判不了**

证据图：`OPEN_DETECT.html`，重新生成 `python3 gen_open_detect.py`。

## 16. 噪声大就测不出力矩吗？——不，问题在"用绝对值还是用差分"

这一节回答两个问题：① 力矩到底能不能测；② 判打滑还能用什么信号。

### 16.1 单向电流确实测不出来（这部分我之前的判断是对的）

拧盖姿态下（J5=66°、臂悬伸 350 mm、J6 在转）：

| 量 | 值 |
|---|---|
| I6 单向 std | **0.0815 A** |
| 折算力矩 | **0.88 N·m** |
| 要分辨的差异（"未开" vs "动了"） | 0.0103 A = **0.111 N·m** |
| **SNR** | **0.13** |

信号比噪声小 8 倍。**单向电流这条路，物理上就是关的。**

### 16.2 但同一姿态下做差分，噪声降 310 倍

K6 标定时做过三次空载重复，这是现成的证据：

```
空载 ΔI 三次：0.1650 / 0.1651 / 0.1656  A
             std = 0.000262 A  (0.16%)
```

对比：

| 量 | 噪声 | 折合力矩 |
|---|---|---|
| 单向 I6 | 0.0815 A | **0.88 N·m** |
| 差分 ΔI | 0.000262 A | **2.83 mN·m** |
| **比值** | **310×** | — |

同一个差异 0.111 N·m：

| 用法 | SNR | 能否分辨 |
|---|---|---|
| 单向电流 | 0.13 | ❌ 完全不行 |
| **同姿态差分** | **39** | ✅ 非常清楚 |

**为什么差分这么有效**：单向电流里的 0.08 A 噪声几乎全是**慢漂**（温漂 + 固件重力前馈残差 + 整臂振动），
它在同一姿态、相近时刻内是**共模的**。做差分时两边一起减掉，只剩真正的差异。

这也解释了 K6 标定为什么必须用正反转差分——静摩擦、重力矩、温漂全部相消，只剩配重力矩。

### 16.3 这就对应论文的 τ_ext = τ_m − τ_f

FACTR 2 的核心恒等式：

```
τ_ext = τ_m − τ_f        τ_f = 自由空间力矩（摩擦+重力+惯性）
```

论文用神经网络学 `τ_f = f_θ(q, q̇, Δq_d)`，监督数据是 **10 分钟无接触自由运动**。
本质就是：**先知道"这一时刻本该是多少力矩"，减掉它，剩下的就是外力。**

我们现在的做法是同类：
- `τ_m = K·I` ✅ 已有（K6 标定过）
- `τ_f` ❌ **缺**——我们没有"张开夹爪跑同一条轨迹"的空载基线

所以现在的 `tau6_ext = K6·|i6| − 0.86` 只是减了一个**常数**摩擦，没有减掉姿态相关的
重力前馈和慢漂。这就是残差这么大（0.88 N·m）的根本原因。

**如果补上空载基线，τ_ext 的噪声预期降到 mN·m 量级。**

### 16.4 具体怎么做（不需要任何新硬件）

```
① 张开夹爪（70mm），跑 twist_log 同一条 q6 轨迹：170° → 0°，15°/s
   → 得到 baseline_i6(q6)，这是"这一姿态下空载的正常电流"

② 夹着瓶盖，跑同一条轨迹
   → 得到 loaded_i6(q6)

③ 按 q6 对齐（不是按时间！），逐点相减
   ΔI(q6) = loaded_i6(q6) − baseline_i6(q6)

④ τ_load(q6) = ΔI(q6) × K6
```

**必须按 q6 对齐**：两次运行的时间轴不可能完全一致（启动延迟、加减速），
但 q6 是位置闭环，同一角度对应同一姿态，所以用 q6 做索引才是对的。

**预期效果**：τ_load 精度 ~0.003 N·m，而打滑/咬住的差异约 0.1 N·m ⇒ SNR ~30。

### 16.5 有了 τ_load(q6) 之后，判打滑就有物理依据了

这是关键——**不是看电流大小，而是看力矩随转角的形状**：

| 状态 | 物理 | τ_load 随转角的表现 |
|---|---|---|
| **打滑** | 夹爪在瓶盖表面滑，摩擦 = 动摩擦 μ_k·F·r | **近似恒定**，与转角无关 |
| **跟着转** | 夹爪带动瓶盖，阻力来自螺纹+密封环 | **随转角变化**（周期结构、密封环释放时台阶下降） |

**判据：τ_load(q6) 的波动幅度。**

```
打滑  →  τ_load 平（std 小）
跟转  →  τ_load 有起伏（std 大，且有周期）
```

这个判据的物理基础比之前所有尝试都硬——**动摩擦恒定 vs 负载随几何变化**，是一阶效应，不是二阶统计技巧。

### 16.6 附带发现：i5 的高频振动能量（候选，证据不足）

顺手测了六个轴电流的高频分量（减去 0.5 s 滑动均值后的 std），看"未开 / 开了"两组的差别：

| 轴 | 未开组 3 份 | 开了组 3 份 | 效应量 d | 是否重叠 |
|---|---|---|---|---|
| i1 | 0.0110 (0.0104~0.0117) | 0.0088 (0.0080~0.0096) | 3.59 | 分离（**方向相反**） |
| i2 | 0.0045 | 0.0059 | 1.01 | 重叠 |
| i3 | 0.0052 (0.0040~0.0063) | 0.0067 (0.0054~0.0074) | 1.62 | 重叠 |
| i4 | 0.0135 | 0.0138 | 0.22 | 重叠 |
| **i5** | **0.0094 (0.0068~0.0121)** | **0.0136 (0.0126~0.0150)** | **2.49** | **分离** |
| i6 | 0.0748 | 0.0798 | 3.82 | 分离 |

**i5 高频：未开 0.0094 → 开了 0.0136（+45%），两组不重叠。**

可能的物理：盖子被咬住时，夹爪与瓶盖是**刚性耦合**，螺纹/密封环的力矩起伏直接传到臂上
→ 振动大；打滑时是**滑动接触**，像一层"软垫" → 振动小。

**但不能当判据用，三个理由**：

1. **只有 3 vs 3**，且不是配对实验（初始扭矩、夹紧位置都不同）
2. **i1 方向相反**（未开时更高），说明不全是"接触刚性"这一个机制在起作用
3. **可能只是"盖已经松了"的指示**——盖松了以后爪子和瓶盖之间有间隙，会产生碰撞振动，
   这跟"是否在打滑"是两件事

**结论**：这是目前唯一在统计上与结果分离的信号，值得再采数据验证，
但**不能写进结论**，也不能当在线判据。

### 16.8 实测修正：跨运行差分的真实降噪能力（比我一开始估的差）

上面 16.2 的 310 倍是**同一次运行内**（正转 vs 反转，间隔几秒）的差分。
跨**两次运行**做差分，条件完全不同，实测下来要差得多。

用 `1.全量原盖未打开` 当"基线"、`4.…_轮2` 当"带载"，沿 q6 做窗口平均：

| q6 窗口 | ≈时长 | ≈帧数 | 单份 std | 差分 std | 实际降噪 |
|---|---|---|---|---|---|
| 0.5° | 0.03 s | 6 | 0.0351 | 0.0365 | 1.0× |
| 1° | 0.07 s | 11 | 0.0232 | 0.0272 | 0.9× |
| 2° | 0.13 s | 23 | 0.0180 | 0.0221 | 0.8× |
| 5° | 0.33 s | 57 | 0.0150 | 0.0195 | 0.8× |
| **15°** | **1.00 s** | **172** | **0.0137** | 0.0179 | 0.8× |
| 20° | 1.33 s | 229 | 0.0140 | 0.0184 | 0.8× |

**两个结论**：

1. **沿 q6 平均是必须的**：窗口 0.5° → 15°，单份 std 从 0.0351 降到 0.0137（**2.6 倍**）。
   因为粘滑是时间上的随机过程，同一个 q6 角度两次可能一次 stick 一次 slip，
   瞬时值差 0.3 A。只有窗口 ≥1 个粘滑周期（15°/s 下约 15°，170 帧 ≈1 s）才平均得掉。

2. **跨运行差分没有额外降噪（0.8×，反而略升）**。原因：
   - 慢漂不是共模的（两次运行间隔几分钟，温漂不同）
   - 粘滑的随机残余在两边各自留下 0.013 A，相减时按方和根叠加 → 0.019 A

**所以 16.4 里"预期 SNR 30"是错的，修正如下**：

| 量 | 值 |
|---|---|
| 窗口平均后的单份噪声 | 0.013 A = **0.14 N·m** |
| 跨运行差分噪声 | 0.018 A = **0.19 N·m** |
| 要分辨的差异（未开 vs 动了） | 0.0103 A = 0.11 N·m |
| **SNR** | **≈0.6** ❌ |

**用"平均差异"判打滑，SNR 只有 0.6，仍然不够。**

### 16.9 但"形状"能看出来——判据应该改成看曲线形状

虽然平均值分不开，**τ_load 随转角的变化幅度是明显的**。同样这两份数据，分 10 段：

| q6 区间 | τ_load 均值 | 段内 std |
|---|---|---|
| 0~17° | −0.56 | 0.14 |
| 34~51° | −0.63 | 0.037 |
| 68~85° | −0.53 | 0.080 |
| 102~119° | −0.90 | 0.030 |
| 136~153° | **−1.00** | 0.028 |

**全程从 −0.56 变化到 −1.00，跨度 0.44 N·m，而段内 std 只有 0.03~0.08。**

跨度的 SNR = 0.44 / 0.08 ≈ **5.5**，是平均值 SNR（0.6）的 9 倍。

**所以判据不是"τ_load 多大"，而是"τ_load 变不变"**：

| 状态 | 物理 | τ_load(q6) 形状 |
|---|---|---|
| 打滑 | 动摩擦 μ_k·F·r，与转角无关 | **平坦**（跨度小） |
| 跟转 | 螺纹 + 密封环，随几何变化 | **有起伏/台阶**（跨度大） |

判据量：`span = max(τ_load) − min(τ_load)`

- 打滑 → span 小
- 跟转 → span 大

**但这个阈值现在还不能定**，因为：
1. 手上没有"确定的打滑"和"确定的跟转"配对数据
2. 上面这组对照里，"基线"其实也是带载的（未开时也夹着瓶盖），不是真空载

必须补真正的空载基线才能标定这个阈值。

## 17. 现在的 τ_f 到底是怎么算的（逐行核对）

### 17.1 代码里只有一行

`twist_log.py:44` 和 `:239`：

```python
TAU_F6 = 0.86                              # 第 44 行，硬编码
...
tau6_ext = K6 * i6a - TAU_F6               # 第 239 行，i6a = abs(i6)
```

展开就是：

```
τ_ext = 10.7882 × |i6| − 0.86
      ≡ 10.7882 × (|i6| − 0.0797)
```

**它本质是一句话：把当前电流减去"空载时的平均电流 0.0797 A"，再乘 K6。**

### 17.2 0.86 的来历（三种算法互证）

来自 K6 标定的**空载点**（`data/k6sweep_r2.csv` 里 τ=0 那一行）：

| 算法 | 计算 | 结果 |
|---|---|---|
| 由 ΔI | 0.1602 × 10.7882 / 2 | **0.864 N·m** |
| 由正转单向 | 0.0795 × 10.7882 | **0.858 N·m** |
| 由反转单向 | 0.0807 × 10.7882 | **0.870 N·m** |

三者一致，所以取了 0.86 这个常数。

### 17.3 它为什么不够——四条

**① 姿态不同**

标定时是 q6 中心 140°、J5=65.7°、夹着 L=120 mm 的钢尺。
拧盖是 q6 从 170° 转到 0°、J5=66°、夹着瓶盖。

减速箱摩擦随**位置和速度**变化（不同啮合相位、润滑膜厚度不同），
所以 0.86 只是那一个姿态下的值。

**② 不随速度变化（这一条实测有明确证据）**

I6 与 |dq6| 是强负相关：

| 文件 | r(I6, \|dq6\|) | 低速段 I6 | 高速段 I6 |
|---|---|---|---|
| 1-未打开 | **−0.313** | 0.171 | 0.137 |
| 4-轮2 | **−0.438** | 0.156 | 0.074 |

速度从 0 涨到 25 °/s，电流降 0.03~0.08 A（=0.3~0.9 N·m）。
常数 τ_f 完全没考虑这一项，这就是论文要把 q̇ 放进网络输入的原因。

**③ 不随时间漂**

同一个 0.86，实测慢漂是 0.015~0.08 A（=0.16~0.86 N·m）。
常数跟不上，所以残差里始终留着这个量级的东西。

**④ 用了 abs()，把回馈帧当成负载（小偏差）**

拧盖时 J6 单向转，电流应该同号。实测：

| 文件 | i6>0 的帧占比 |
|---|---|
| 1-未打开 | 0.0% |
| 3-轮1/2/3 | 0.0 / 0.3 / 0.1% |
| 4-轮1/2/3 | 0.2 / **3.5** / **3.8%** |

4-轮2/3 有 3.5~3.8% 的帧电流变正（电机在回弹/减速，不是在出力）。
`abs()` 把它们当成"有负载"，把 τ_ext 抬高：

```
4-轮2 里 81 个正帧
  abs 口径 ：τ 均值 −0.611  （看起来像有负载）
  signed  ：τ 均值 −1.109  （明确是负的，在回馈）
```

影响量级 0.018 N·m（全段均值），**不大，但方向是错的**——修法是用 `−i6` 而不是 `abs(i6)`。

### 17.4 更根本的问题：τ_ext 的绝对值完全取决于基线怎么选

同一批数据，换基线方式，τ_ext 的"绝对值"就完全变了：

| 基线方式 | 1-未打开 τ 均值 | 4-轮2 τ 均值 | 两者差 |
|---|---|---|---|
| **常数 0.08 A（现在）** | **+1.19** | **+0.48** | **0.71** |
| 本轮 P5 | +1.165 | +1.155 | **0.01** |
| 本轮 P10 | +0.981 | +1.014 | −0.03 |
| 本轮 P20 | +0.733 | +0.809 | −0.08 |

**用常数基线时，未开和开了差 0.71 N·m（看起来能分）；
用本轮自己的低分位当基线时，两者几乎一样（差 0.01）。**

原因：4-轮2 的 P5 只有 0.017 A（因为盖已松，有大量接近零的帧），
基线一降，τ_ext 就被抬到和"未开"同一个水平。

**结论：τ_ext 的绝对值是一个"随基线假设漂移"的量，不能拿来判状态。**
只有它**随转角的变化形状**是稳的（这也是 §16.9 的结论）。

### 17.5 和论文的差距在哪

```
论文：τ_f = f_θ(q, q̇, Δq_d)      神经网络，10 分钟自由运动训练
我们：τ_f = 0.86                  一个数
```

论文的 τ_f 能吃掉：姿态、速度、加速度、摩擦的历史依赖、温漂（间接）。
我们的 0.86 只能吃掉"某一个姿态、某一段时间、某一个速度下"的平均摩擦。

**这就是为什么论文的 τ_ext 能直接拿去判接触（FIRST 的 T_high 判据），
而我们的 τ_ext 只能看趋势。**

要缩小这个差距，最小改动是 §16.4 的空载重放（用实测基线代替常数），
最大改动才是照论文训练一个网络。

### 17.6 如果只改一处，先改这个

**不建议**动 0.86 这个数（换了姿态还是要重标）。

**建议**改成：

```python
tau6_ext = K6 * (-i6) - tau_f(q6, dq6)      # 有符号 + 随姿态
```

其中 `tau_f` 用空载重放数据插值得到（`twist_diff.py` 已经是这个思路）。
这样 τ_ext 才是真正"减掉正常值之后剩下的外力"，也才配得上叫 τ_ext。

## 18. NEXT 模型能不能判打滑/开盖？——实测：不能，差 6~13 倍

### 18.1 怎么测的

写了一个脚本 `20261020_stage4/next_verify.py`，把训练好的 NEXT 模型（`runs/kfold/kf0`，
H=75、LSTM 2×128 + MLP 2×256、残差模式）拿去预测拧盖数据：

```
拧盖 csv（186 Hz、度）
  → 转弧度、重采样到训练用的 50 Hz（**这一步必须做，训练是 50 Hz**）
  → 按 H=75 滑窗喂进模型
  → 反归一化 + 加回残差基线 [q,1]@lin_W
  → 与实测 τ = K·I 对比
```

同时拿**训练集内的段**做同样处理，确保是模型问题而不是脚本问题
（第一次跑时确实是我脚本的 bug：漏了加回 `lin_W`，预测全接近 0；修正后训练集内 MAE 从 1.23 降到 0.28）。

### 18.2 训练集内：J2/J3 很准，J6 很差

| 段 | 总 MAE | J2 MAE | J3 MAE | **J6 MAE** |
|---|---|---|---|---|
| M4_J4J5J6 | 0.346 | 0.127 | 0.355 | **1.246** |
| V2_J5J6 | 0.268 | 0.341 | 0.261 | **0.630** |
| T2_J1J6 | 0.298 | 0.268 | 0.554 | **0.640** |
| S1_1_mid | 0.281 | 0.284 | 0.463 | **0.758** |

| 轴 | 训练标签 std | J6 的 MAE/信号比 |
|---|---|---|
| J2 | 2.84 N·m | 0.13~0.34 → **0.05~0.12**（很好） |

**总 MAE 0.28 看起来漂亮，但那是 J2/J3 拉出来的。J6 单独看是灾难。**

### 18.3 拧盖姿态：全部失效

| 轴 | 实测 K·I | NEXT 预测 | 差 |
|---|---|---|---|
| J1 | 0.071 | −0.004 | −0.076 |
| J2 | −7.309 | −8.744 | **−1.436** |
| J3 | −3.079 | −6.625 | **−3.546** |
| J4 | 0.128 | 0.165 | 0.037 |
| J5 | −0.018 | −0.775 | −0.757 |
| **J6** | **−1.284** | **+0.090** | **+1.374** |

J6 细看：

```
实测 τ6: −3.80 ~ +1.01 N·m   均值 −1.28   跨度 4.81
预测 τ6: −0.04 ~ +0.19 N·m   均值 +0.09   跨度 0.23
误差:    均值 +1.37  std 0.77  最大 3.99 N·m
```

**预测的跨度只有 0.23 N·m，而实测跨度 4.81 N·m —— 模型完全没跟住。**

### 18.4 三层原因（越来越根本）

**第一层：姿态外推。** 拧盖姿态在三个轴上都超出训练范围：

| 轴 | 拧盖 | 训练集范围 | 偏离 |
|---|---|---|---|
| **J1** | **150.1°** | −9.9 ~ 9.9° | **15 倍** |
| J2 | 117.3° | −0.2 ~ 120° | 接近上限 |
| J3 | −87.3° | −140 ~ −12.9° | 范围内 |
| J4 | 2.4° | −9 ~ 60° | 范围内 |
| **J5** | **65.8°** | −70.2 ~ 52.1° | **超 13.7°** |
| **J6** | **170→0°** | **0 ~ 90°** | **170° 段完全没数据** |

残差基线 `[q,1]@lin_W` 是**线性**的，J1 从 10° 外推到 150° 必然给荒谬值。
这解释了 J2/J3 差 1.4/3.5 N·m。

**第二层：J6 的力矩本来就不该从运动学预测。**

自由运动时 J6 力矩的 std 只有 **0.038 N·m**（几乎不变），而 MAE 有 **0.63~1.25**。
误差是信号的 16~33 倍，说明模型输出基本是"0 附近的常数"，与实测无关。

为什么？自由运动时 J6 的力矩主要不是**重力/惯性**，而是**减速箱静摩擦**（一个近常数偏移，
实测均值约 −0.84 N·m）。静摩擦大小取决于啮合相位、润滑、温度、停留时间——
**不由 q、q̇ 决定，所以网络没法预测，只能平均掉。**

**第三层（最要紧）：打滑信号恰恰被当成噪声丢掉了。**

打滑的物理本质就是**摩擦状态切换**（静摩擦↔动摩擦）。而 J6 力矩里，
"摩擦"正是那个 **NEXT 学不会、被它当噪声平均掉**的成分。

⇒ **模型越是"训练成功"（把 J6 的力矩拟合到 0），就越会把打滑信息抹掉。**

这不是调参能解决的，是方法定位问题：NEXT 是为"接触外力"设计的，
它把摩擦看作要消除的干扰；而我们要观测的，正是摩擦本身。

### 18.5 差距有多大

| 需求 | 精度要求 | NEXT 实际 |
|---|---|---|
| 判"未开 vs 动了" | **0.11 N·m** | 分布内 J6 MAE 0.63~1.25；拧盖姿态 1.37 |
| 判"τ_load 随转角的形状"（span） | 段内 std 0.03~0.08 | 同上 |
| **差距** | — | **6~13 倍** |

### 18.6 那 NEXT 在这个项目里还有没有用

**有，但不是用在这里。**

| 场景 | NEXT 适用性 |
|---|---|
| 检测"有没有接触/碰撞"（论文的 FIRST 用法） | ✅ 适用——0.3~0.5 N·m 的力足够，且 J2/J3 准 |
| 末端外力方向估计（L2 称重，Φ 已标定） | ✅ 已用过，0.3 kg 误差 3.0% |
| **判拧盖是否打滑** | ❌ 不适用——差 6~13 倍，且方法定位相反 |
| **判瓶盖是否打开** | ❌ 不适用——同上下 |

### 18.7 如果一定要用学习方法做打滑检测

正确的做法不是"预测力矩再减掉"，而是**直接学习打滑状态**，而且要用**外部标注**：

```
输入：q, q̇, i6, i2, i3, i5（含高频分量）, grip_effort
标签：人工标注"这一帧瓶盖有没有跟着转"（视频/标记/二值上提法）
```

也就是把它做成**分类**而不是回归，标签来自外部测量，而不是试图从电流里"算"出来。

但这需要先有标注——又回到"必须有外部转角测量"这个前提。
**绕不开。**

### 18.8 本节结论（一句话）

**NEXT 测得准 J2/J3（重力主导），测不准 J6（摩擦主导）；
而拧盖完全依赖 J6。所以 NEXT 判不了打滑，也判不了开盖——差 6~13 倍。**
