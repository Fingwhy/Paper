## 3. 12 列是什么

```
t_s, cmd_q6, meas_q6, i6, i1, i2, i3, i4, i5, i6_dup, grip_angle, grip_effort
```

| # | 列 | 单位 | 说明 |
|---|---|---|---|
| 1 | `t_s` | s | 从开始 twist 计时 |
| 2 | `cmd_q6` | ° | J6 指令角（斜坡生成） |
| 3 | `meas_q6` | ° | J6 实测角（`0x2A5~0x2A7`） |
| 4 | **`i6`** | **A** | **J6 电流**（`0x256`）← 拧盖关键量 |
| 5–9 | `i1`–`i5` | A | J1–J5 电流（`0x251`–`0x255`） |
| 10 | `i6_dup` | A | 重复写的 i6。**旧文件表头缺这一列**（11 列），别用 `DictReader` 读 |
| 11 | `grip_angle` | 0.001 mm | 夹爪开度，除 1000 得 mm |
| 12 | `grip_effort` | 0.001 N·m | 夹爪力矩反馈，负 = 夹紧方向 |

读取口径：

```python
p.GetArmHighSpdInfoMsgs().motor_N.current * 0.001   # A，N=1..6
```

⚠️ 字段名是 `current`，**不是** `motor_current`。
⚠️ 不要用 `LowSpd.bus_current`（`0x261`），1.5 kg 机型这个字段未采样。

### ⚠️ 采样率别搞混（重要修正）

| 层 | 频率 | 说明 |
|---|---|---|
| CAN 反馈帧（`0x251`~`0x256`） | **200 Hz** | 硬件刷出率 |
| **`twist_*.csv` 实际落盘** | **≈ 48~49 Hz** | `DT_SEND` 循环 + 开销 |

实测：`r1` = 2835 帧 / 58.5 s = **48.5 Hz**；`z177` = 568 帧 / 11.7 s = **48.5 Hz**。
**之前说"200 Hz 记录"是错的**，实际只有 49 Hz，即每 20 ms 一个点。

后果：单帧抖动更"块"（相邻点间隔 20 ms），分析 stick-slip 这类高频现象时分辨率不够。
若要真 200 Hz，需改 `twist` 里的 `DT_SEND=0.005` 重采——**已有数据无法追溯**。

## 4. 电流精度：官方查证结果

**结论先说：厂家从来没有公布电流测量精度。**

查了这几个来源：

| 来源 | 有电流精度吗 |
|---|---|
| 官网产品页 / 产品单页（agilex.ai、scengrobotics） | **没有**。只有负载 1.5 kg、重复定位 ±0.1 mm、工作半径 626 mm、关节范围、最大速度、功耗 |
| 快速入门手册（Quick Start） | **没有**。只给关节范围、最大速度、CAN 接口 |
| `piper_sdk` 消息定义（V1/V2） | 只给**单位**，无精度 |
| `PROTOCOL_V1.MD` | 只给编解码方法，无精度 |
| 第三方 Rust 重实现（docs.rs `piper-sdk`） | 只给单位与符号，无精度 |

### 能确定的（协议层，硬事实）

| 项 | 值 | 出处 |
|---|---|---|
| 帧 ID | `0x251`~`0x256`（J1~J6） | 协议定义 |
| 字段 | `current`，2 字节 | — |
| 单位 | **0.001 A / LSB** | SDK 注释 |
| 类型 | **有符号 `int16`** | 实测出现负值（J2 = −1.85 A） |
| 量程 | **−32.768 ~ +32.767 A** | `int16 × 0.001` |
| 帧率 | 200 Hz | 实测 |
| **量化步长** | **1 mA** | = 单位 |

### 两个坑

**① 官方 SDK 消息定义把 `current` 写成 `uint16`，这是错的。**
DeepWiki 的字段表明确列 `uint16 Current (0.001A)`。但实际是有符号 `int16`——
我们数据里 J2 常态 −1.78 A、J6 常态 −0.21 A，用无符号解根本读不出来。
（第三方 Rust 实现写的是 `i16`，与实测一致。）

**② 1 mA 是分辨率，不是精度。**
两者差 100 倍以上（见 §5）。精度取决于驱动器的采样电路、温漂、滤波，厂家未公开，
**任何引用"±x% FS"的说法都是编的**。要谈精度只能用实测噪声。

### 官方力矩系数（仅供对照）

SDK 参考实现给了电流→力矩的标称系数：

| 关节 | 官方系数 (N·m/A) | 我们实测 K | 比值 |
|---|---|---|---|
| J1–J3 | 1.18125 | J2=J3=**4.7185** | **4.00×** |
| J4–J6 | 0.95844 | J4=J5=**0.7446** | 0.78× |
| J4–J6 | 0.95844 | J6=**10.7882** | **11.26×** |

**官方系数只在 J4/J5 附近接近实测**，J2/J3 差 4 倍、J6 差 11 倍。
所以力矩必须用自己标定的 K，不能用官方系数。（4× 的成因未查清，别写成"漏乘减速比"。）

## 5. 实测噪声（工程上唯一能用的"精度"）

方法：用拧盖数据里**全程静止**的 J1–J5 的电流波动当纯噪声。
数据源 `twist_z177.csv`（568 帧，q6 170→0，J1~J5 不动）。

| 轴 | 标准差 | 峰峰 | 状态 |
|---|---|---|---|
| J1 | **0.0159 A** | 0.097 | 静止 → 纯噪声 |
| J2 | 0.0263 A | 0.161 | 静止 |
| J3 | 0.0395 A | 0.284 | 静止 |
| J4 | 0.0478 A | 0.236 | 静止 |
| J5 | 0.0866 A | 0.396 | 静止 |
| **J6** | **0.0704 A** | 0.293 | 静止（尾部保持段） |

### 三条要紧的推论

**① 噪声比分辨率大两个数量级。**
分辨率 0.001 A，实际噪声 0.016~0.087 A，**50~90 倍**。

**② 滑动平均几乎无效。**
J1 经 25 帧（0.5 s）平均后 std 从 0.0159 只降到 0.0147（**降 8%**）。
说明噪声是**低频漂移**（温漂 + 机械振动 + 固件重力前馈残差），不是白噪声，
多采几百点也平均不掉。

**③ J6 折算到力矩，噪声地板 = 0.76 N·m**

```
0.0704 A × 10.7882 N·m/A ≈ 0.76 N·m
```

而拧盖过程中扭矩的变化量只有 0.46 N·m（1.45 → 0.99）——**比噪声地板还小**。
这是"I6 不能做拧开程度判据"的硬定量依据。

（注：阶段 4 报告的 0.111 N·m 是台面标定姿态。这里 J5≈66°、臂悬伸 350 mm，
机械振动大得多，所以差 7 倍。**不同姿态的噪声不能互相引用。**）

### 静止时电流也不为零

`z177` 的静止轴电流：J1 = +0.083 A、J2 = −1.78 A。
J2 的 −1.78 A 是重力矩前馈，J1 的 +0.083 A 是零点偏置。
**所以只能看差分 ΔI，不能看绝对值**——这正是 K6 标定必须用正反转差分的原因。

## 5b. "咬住判据"的实际准确率（修正上一轮的说法）

判据定义：`I6 末段均值 / 首段均值`，**< 0.90 判为"后半程咬住"**，否则"疑似打滑"。
物理依据：I6 高 = 夹爪在瓶盖表面滑动，I6 低 = 咬住了只剩螺纹阻力。

用 29 条实测数据核对（排除 r1/r2 人工预松、cyc1–3 作废、fast2 污染）：

**只看完整 170° 扫掠的 13 条：**

| 判据结论 | 条数 | 其中真的拧开 | 命中率 |
|---|---|---|---|
| **咬住**（<0.90） | 5 | **4**（fast12、dn2mm、dn2mm_b、z177；**log1 未开**） | **4/5 = 80%** |
| 打滑（≥0.90） | 9 | 2（fast15b 0.95、rc3 0.98） | 7/9 = 78% |

**结论**：
- ⚠️ **"咬住"只是必要条件，不是充分条件**——完整扫掠里 <0.90 的 5 次中 4 次拧开，
  **`log1`（bite 0.80）判"咬住"却没拧开**。判据值低说明"真的在转"，但不代表已经脱扣。
- ❌ **"打滑"不能反推"没开"**——`fast15b`（0.95）和 `rc3`（0.98）也在打滑区，但都动了。
- ⚠️ **短段/脱开瞬间判据失效**：`fast1` 只有 30°、251 帧，比值 1.62（末段反而升高），
  可它恰好是把瓶盖拧开的那一次——脱开瞬间夹爪带盖在螺纹上空转、挤压更紧，摩擦反而增大。

**所以上一轮"零例外"的说法是过度结论，收回。** 实际用法：

```
判据 < 0.90  → 可以放心继续拧（4/4 都成了）
判据 ≥ 0.90  → 不能断定失败，只能说明"前 170° 里大部分在打滑"，
               多拧一轮再看，或用 --by-angle 检查转折点在哪
```
