# 60 秒真静止实验：J3 电流噪声到底是什么

> 日期：2026-10-21
> 数据：`episodes/DRIFT1/`（100 Hz 解析，VM 与 Windows 各一份）
> 目的：验证「在每段首尾加静止基线、把 J3 慢漂移扣掉」这个设想是否成立。
> 结论：**不成立。J3 的误差不是可扣除的漂移，扣完只改善 0.3%。**

---

## 1. 实验条件

- 机械臂在 CAN_CTRL 使能状态下保持当前姿态 **70 s**，全程有指令（`stage1_cmd.py hold`，100 Hz 下发）。
- 姿态：`[-0.3, -0.19, -15.94, 3.10, 22.02, 0.00]` deg
- **真的没动**：六轴位移 0.000°，峰峰 0.000°（100 Hz × 7000 样本）。
  （对比：阶段 3 的 H1_hold_A「静止保持段」峰峰其实有 2.4~3.0°，不算真静止。）
- 采样：原始 200 Hz，解析 100 Hz，`0x251~0x256` 每路 14000 帧，无丢帧。
- 原始文件 14.7 MB / 70 s ⇒ 200 Hz 全帧落盘，1 小时采集约 750 MB，磁盘（剩 19 GB）够。

---

## 2. 电流噪声（单位 A；乘 K 得 N·m）

| 轴 | std (A) | std (N·m) | lag-1 自相关 | 31 帧均值后 std (N·m) |
| --- | --- | --- | --- | --- |
| J1 | 0.0186 | 0.0879 | 0.955 | 0.0815 |
| J2 | 0.0254 | 0.1196 | 0.960 | 0.1139 |
| **J3** | **0.0647** | **0.3054** | **0.996** | **0.3038** |
| J4 | 0.0480 | 0.0357 | 0.987 | 0.0345 |
| J5 | 0.0544 | 0.0405 | 0.987 | 0.0391 |
| J6 | 0.0202 | 0.0150 | 0.782 | 0.0121 |

J3 自相关：lag(1, 2, 5, 10, 20, 50, 100) = `0.996, 0.996, 0.994, 0.991, 0.980, 0.914, 0.732`

**读法：**
- **不是白噪声**（lag-1 = 0.996，1 秒后还有 0.732）⇒ 是**慢变随机游走**，相关时间约 2~3 s。
- **不是线性漂移**：去线性趋势后 std 仍 0.064（原 0.065），去二次也一样 ⇒ 扣趋势无效。
- **平均也救不了**：31 帧（0.31 s）平均后 0.3038 vs 0.3054，只降 0.5%。
- 净变化很小（70 s 只漂 0.006 A），但**瞬时波动 ±0.06 A**——它在零附近来回游走，
  不是往一个方向走。

---

## 3. 直接检验「段首尾基线法」

用首 5 s 与末 5 s 的均值连一条基线，从整段里减掉：

| 轴 | 原始 std | 扣常数后 | 扣首尾线性基线后 | 改善 |
| --- | --- | --- | --- | --- |
| J1 | 0.0187 | 0.0187 | 0.0186 | −0.5% |
| J2 | 0.0258 | 0.0258 | 0.0308 | **+19.7%（更差）** |
| **J3** | 0.0645 | 0.0645 | **0.0643** | **−0.3%** |
| J4 | 0.0483 | 0.0483 | 0.0406 | −16.0% |
| J5 | 0.0551 | 0.0551 | 0.0549 | −0.2% |
| J6 | 0.0201 | 0.0201 | 0.0201 | +0.2% |

**J3：0.304 N·m → 0.303 N·m。等于没扣。**

原因就是第 2 节：段内是随机游走，首尾基线只能代表两个时刻的值，
中间怎么走完全不知道；线性插值反而可能引入偏差（J2 变差 20% 就是证据）。

---

## 4. 这个数字和 L1 的误差对上了

- 阶段 4 的 J3 单帧 MAE = **0.343 N·m**（占总误差 40%）
- 本次测得的 J3 噪声地板 = **0.305 N·m**
- 比值 1.12 ⇒ **L1 在 J3 上只比噪声地板高 12%，已经在极限附近。**

而噪声来自驱动器维持位置的电流环抖动（只要使能就有，不是采集问题、
不是模型问题、也不是标定问题）。**除非换硬件或改驱动器固件参数，否则不可降。**

---

## 5. 对原计划的影响（重要）

原定「重新采集 90 分钟」有三条理由，逐条结算：

| 理由 | 结论 |
| --- | --- |
| ① 段首尾静止基线，扣掉 J3 漂移（占误差 40%） | **否证**：只能扣 0.3% |
| ② 采样率 50→100 Hz 降 dq 量化噪声 | **收益很小**：dq 来自驱动器速度字段，不靠位置差分；且 R65 已证 dq 相对 q 只增 9.6% |
| ③ 段数 49→70，test 5→10 段，降低评估噪声 ±17% | **成立，但可以用 5-fold 交叉验证更便宜地达到**（本机 50 min，零人工） |

⇒ **不建议为此跑 90 分钟全量重采。** 应当先做 5-fold，把「哪个配置真的好」
这个问题回答清楚；硬件留着做真正需要新数据的事（阶段 6 的 FIRST 接触标注）。

## 6. 复现步骤（VM `~/stage0/`）

```bash
# 1) 拉 CAN（三步，必须查 bitrate）
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -d link show can0 | grep bitrate      # 必须看到 bitrate 1000000

# 2) 断电重启后先切 CAN_CTRL（空闲 10 min 会回落 TEACHING）
cd ~/stage0/20261019_stage0/scripts
python3 stage0_probe.py --iface can0 --phase sdk --allow-write --to-can-ctrl

# 3) 后台录制 70 s，同时 hold 60 s
cd ~/stage0/20261019_stage1_l0
nohup python3 stage1_l0.py record --iface can0 --seconds 70 \
      --out ~/stage0/20261020_stage4/raw/DRIFT1.jsonl > /tmp/rec.log 2>&1 &
sleep 3
python3 stage1_cmd.py hold --iface can0 --duration 60 --out cmd/hold_drift1 --yes

# 4) 按 100 Hz 解析（可见 50 Hz 只是后处理选择）
python3 stage1_l0.py parse ~/stage0/20261020_stage4/raw/DRIFT1.jsonl \
      --hz 100 --pos251-unit mrad --qcmd cmd/hold_drift1.csv \
      --out ~/stage0/20261020_stage4/episodes/DRIFT1
```

产物同步：`episodes/DRIFT1/{samples.jsonl, metrics.json, sync_report.md}`。
