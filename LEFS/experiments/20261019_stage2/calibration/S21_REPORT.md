# 阶段 2 · S2-1 力矩常数 K 标定 —— 收口报告

> 数据：2026-10-20 · AgileX PiPER（带夹爪，末端 0.500 kg）· 载荷 = 水瓶 0.525 kg（连瓶带水带胶带）
> 方法：同姿态「空载 − 带载」差分 · 10 个姿态 · 静止段最后 30 s
> 交付：`calibration/k_table.json`（主）· `k_table_free.json`（无约束对照）· 本报告

## 0. 结论摘要

| --- | --- | --- | --- | --- |
| J1 | — | — | — | **未标定**（重力平行于轴，τ₁≡0） |
| J2 | **4.719** | 11.8% | 4.00× | **已标定** |
| J3 | **4.719** | 11.8% | 4.00× | **已标定** |
| J4 | **0.745** | 79.6% | 0.78× | **弱约束** |
| J5 | **0.745** | 79.6% | 0.78× | **弱约束** |

水瓶质心（link6 系，拟合值）：**c6 = (−7.2, +7.2, +80.9) mm**，|c6| = 81.6 mm。

**核心发现**：SDK 的**分组结构正确**（J1–J3 一组、J4–J6 一组），但**绝对值不对** ——
实测大关节/腕关节比 = 4.719 / 0.745 = **6.3 倍**，而 SDK 只给 1.181 / 0.958 = **1.23 倍**。
若直接把 SDK 系数当力矩换算用，J2/J3 会**低估 4 倍**。

## 1. 方法：为什么必须走差分

### 1.1 先用全量回归试过，失败了

最初的方案是「URDF 重力矩 τ_arm(q) 对电流 I(q) 做全量回归」。实测判死：

- 跨姿态相关性 J2 全点 r = +0.59，但**只取带载 4 点时 r = −0.61**；
- J3 r = −0.95、J5 r = −1.00，**全部反号**；
- χ²/dof 达 **1204**。

结论：**URDF 的连杆质量分布与这台机器不符**。这条路走不通，不是调参能救的。

### 1.2 差分法为什么能绕开

同一姿态下分别采「空载」与「带载」，相减：

```
ΔI_j = I_j^空 − I_j^带 = τ_pay,j(c6) / K_j + δ_j
```

`τ_pay,j` 是**载荷单独贡献的力矩**，只依赖：

- 运动学（URDF 的**几何**是可信的，质量不可信）；
- 已知载荷质量 0.525 kg；
- 未知质心 c6（作为拟合量）。

臂自重 τ_arm、固件重力前馈、连杆质量误差 —— 这些都只依赖姿态、在同一姿态相减时**整体抵消**。
这是本方法唯一能用的根本原因。

### 1.3 一个容易踩的坑：`p0` 项

`tau_point_force(q, link6, local, F)` 的 `local` 是「**相对法兰原点的偏移**」，不是 link6 系绝对坐标。
所以 `local = 0` 时力矩**不为零**：

```
τ_pay(c) = p0 + Σ c_i · A_i        # p0 = tau_point_force(..., [0,0,0], F)
```

早期版本漏了 `p0`，把 P1 姿态的载荷力矩从 1.13 算成 0.48 N·m，拟合结果荒谬到
c6 = [+25, −262, +3] mm、J4 K = +59。补上 `p0` 后自测与实测才自洽。

### 2.2 采集过程中的两次事故（都写进了闸门）

**① K8 → K5 触发高度守卫，臂在瓶底 30 mm 处原地抱住。**

守卫拦对了，但暴露一个真缺陷：闸门按「六轴等比插值」采样路径，固件实际是「各轴同角速率」走。
K8→K5 里 J2/J3 只走 15°/20°（6~8 s 到位），J4/J5 要走 60°/80°（24~32 s），
中间那段臂是「伸出去、腕还没转回来」，瓶子朝下戳台面。
**旧口径报 +82 mm，真实轨迹 −108 mm。**

已修：`path_min` 改 `mode="rate"`，并加回归测试（自测 J 条）锁死这个口径。

**② 采到 K9R 时 USB-CAN 瞬时重新枚举。**

内核日志 `USB disconnect (device 6)` → 22 s 后 `new device number 7`。
掉线发生在 K9R **已到位之后**的保持段，臂停在 `(0, 60.07, −50.03, 90.04, 39.97, 0)`，
电源未断、`ctrl_mode` 仍为 `CAN_CTRL`。恢复三步拉起 can0（down → bitrate 1000000 → up）后继续。

**③ 拆水瓶时用户断电重启。**

上电后 `ctrl_mode = TEACHING_MODE(0x2)`（不是 STANDBY），臂自由落在竖直收拢位
`(0.08, −0.16, −0.21, 3.13, 19.78, 0)`，法兰 z = 183.5 mm，未碰撞。
必须 `stage0_probe.py --allow-write --to-can-ctrl` 才能接收指令。

### 2.3 空载轮为什么要换几何判据

拆瓶后若仍按「水瓶 22 cm 胶囊」判，会把**本来安全**的起点判死：
该落点夹爪向前下 14°、掠过立柱顶角、最近 **18.7 mm**（臂物理地待在那儿，没碰到任何东西），
而带载口径报 −16 mm。

新增 `--no-bottle`：载荷包络改为「夹爪轴线 0→110 mm」，**横向不膨胀**。
一开始取 45 mm 半宽当胶囊，端部半球外凸，同一落点判出 −27 mm —— 重复扣了轴向那一份。
夹爪是圆柱不是胶囊，端面平，轴向不膨胀才对（横向擦碰由运行时电流守卫兜底）。

## 3. 结果

### 3.1 质心：解释了「水瓶是斜着的」

**c6 = (−7.2, +7.2, +80.9) mm**

- **沿工具轴 81 mm** —— 瓶子 22 cm 长绑在夹爪上，质心落在前半段，合理；
- **横向各 7 mm** —— 这就是用户说的「J6 归零后夹爪并不竖直、水瓶倾斜」的定量体现。
  它必须按**刚性固定在 link6 系**建模（随腕部倾斜），不能按吊挂建模。

横向偏心 7 mm 的直接证据：J6 从 0° 转到 90° 会改变横向偏心在重力场中的投影，
实测 ΔI₆ 峰峰 0.099 A，正比于这个 5~7 mm。

### 3.2 K

自由拟合（每轴独立 K）给出 J2 4.536 / J3 3.942 / J4 0.684 / J5 0.626，
但**留一法下 K4/K5 偏离 107%/109%**，而解析 σ 只报 2.8%/1.3% —— 判据被严重低估。

根因是 **c6 与 K 的简并**：

```
τ_pay_j(c) = p0_j + A_j·c        ΔI_j = τ_pay_j(c)/K_j + δ_j
```

当各姿态的 `A_jz / p0_j` 比例接近时，把 c_z 调大一点、同时把 K_j 调大同样比例，
几乎不改变预测值。于是每个姿态都拟合得好，但 K 随扣掉哪个姿态乱跳。

**加固：组内等系数约束**（K2 = K3、K4 = K5，依据 SDK 的分组结构）：

| | c6 (mm) | K(J2=J3) | K(J4=J5) | χ² | dof |
| --- | --- | --- | --- | --- | --- |
| 无约束 | (−0.5, +5.3, +60.2) | 4.536 / 3.942 | 0.684 / 0.626 | 17.16 | 29 |
| **组约束** | (−7.2, +7.2, +80.9) | **4.719** | **0.745** | 17.97 | 31 |

**Δχ² = +0.81（Δdof = 2）** —— 约束被数据完全接受，不是硬压出来的。
约束把 4 个 K 减到 2 个，c6 随之可辨识，χ²_red = 17.97/31 = **0.58**。

## 4. 交叉验证：留一法

每次扣掉一个姿态，用剩下 9 个重解 c6 与 K，再**预测被扣掉那个姿态的 ΔI**。

| 留出 | K_A (J2=J3) | K_B (J4=J5) | c6 (mm) | χ² |
| --- | --- | --- | --- | --- |
| LIFT | 4.901 | 0.799 | [−7,+7,+92] | 17.49 |
| **K3** | 4.477 | **1.404** | [−14,+14,+228] | 15.61 |
| K10 | 4.882 | 0.800 | [−7,+7,+92] | 15.15 |
| K15 | 4.736 | 0.733 | [−7,+7,+79] | 16.42 |
| K14 | 4.741 | 0.757 | [−7,+7,+83] | 17.55 |
| K9 | 4.140 | 0.593 | [−7,+3,+48] | 10.31 |
| K8 | 4.920 | 0.798 | [−7,+7,+92] | 16.39 |
| K2 | 4.676 | 0.731 | [−7,+7,+79] | 17.08 |
| K9R | 4.922 | 0.798 | [−7,+7,+92] | 16.74 |
| P1 | 4.593 | 0.699 | [−7,+7,+70] | 14.39 |

- **K_A：4.699 ± 0.247，最大偏离 11.8%** → 稳定，可交付；
- **K_B：0.811 ± 0.218，最大偏离 79.6%** → 弱，且原因明确（见下）。

**K3 是唯一的杠杆点。** 10 个姿态里只有 K3（J3 = −110°、J5 = −40°）给出 J3 与 J5 的**负向**激励
（ΔI₃ = −0.149、ΔI₅ = −0.730，其余姿态这两个轴全是正的）。
扣掉它，J5 的数据就退化成「一组几乎相同的正数」，拟合斜率失去约束、c6_z 冲到盒子边缘 228 mm。

这不是数据质量问题（K3 的静止段同样干净），是**姿态设计覆盖不足**。

## 5. 与 SDK 初值对比

SDK（`arm_feedback_high_spd.py:84`，`effort = cur_raw × coeff`）给：
J1–J3 = **1.18125**、J4–J6 = **0.95844** N·m/A。

| | 实测 | SDK | 倍数 |
| --- | --- | --- | --- |
| J2 / J3 | 4.719 | 1.181 | **4.00×** |
| J4 / J5 | 0.745 | 0.958 | **0.78×** |
| 大关节 / 腕关节 | **6.33** | **1.23** | 5.1× |

**分组对、绝对值不对。** 实测的 6.3 倍差更符合「肩肘大关节 vs 腕部小关节」的典型减速比差异
（SDK 的两组几乎相等，反而反常）。J5 的 0.745 与 SDK 0.958 相差 22%，在标称值的个体差异范围内。

**可用结论**：把 SDK 系数用于力矩换算时，J2/J3 会低估约 4 倍。
后续若要做外力/碰撞估计，必须用本表的 K。

## 6. 局限（明确写出来，不掩盖）

| 项 | 状态 | 原因 | 补强方法 |
| --- | --- | --- | --- |
| J1 | 未标定 | 重力方向与 J1 轴平行，静止时 τ₁ ≡ 0 | 滑轮 + 测力计**切向**拉（径向拉也是 0） |
| J6 | 未标定 | τ₆ 跨度仅 0.054 N·m，σ_K/K = 21% | 偏心横杆 **80 mm**，把 τ₆ 放大 ~16 倍 |
| J4/J5 | 弱约束 | 唯一负向激励点 K3 一旦缺失即退化 | 增加 J5 < −40° 且 J4 ≠ 0 的姿态 2~3 个 |
| c6_z | ±49 mm | 与 K 简并 | 同上；或独立称量质心位置作先验 |

另外两点方法层面的说明：

1. **K 的用途是「相对力矩」**：`Δτ_j = K_j · ΔI_j`（相对某个无外力基线）。
   绝对力矩 τ = K·I 需要建立「空载电流 ← 姿态」的基线表，而那张表依赖 URDF 质量（已判不可信），
   所以目前**不要**用它算绝对重力矩。
2. **电流符号**：固件电流与 URDF 力矩约定**反号**（ΔI 与 τ_pay 同号，这是因为 ΔI 定义为「空−带」）。
   使用时注意方向，不要把符号当成 K 的性质。
