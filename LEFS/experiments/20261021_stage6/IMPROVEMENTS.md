# 还可以改进的地方（2026-10-27）

按「收益 ÷ 成本」排序。P0 = 不做则结论不可靠，P1 = 明显提升质量，P2 = 长期。

---

## P0-1　K6 = 0.3889 是**推导值**，不是测量值 ⚠️ 最大隐患

**问题**：现在这个数是 `10.7882 ÷ 27.74` 算出来的，27.74 来自传感器 k 的修正。
也就是说 **K6 的正确性完全建立在「传感器 k 修正正确」之上**——如果 k 的修正只对了一部分
（比如实际 k 是 0.0009 而非 0.001），K6 会跟着错同样比例。

**现状证据**：间接验证很强（实验一反解 K=0.39、比值 0.99、力矩平衡成立），
但**从来没有用独立于传感器的方法直接测过 K6**。

**怎么改**：做一次「静态砝码 + 电流」直接测 K6，完全不碰传感器：
1. 臂到 140°（J6_LEVEL），J6 位置保持
2. 夹爪夹横杆，**量准力臂 L**
3. 杆一端挂已知重物 → 力矩 τ = m·g·L
4. 读 i6（稳定后）
5. 换到另一端挂 → 读 i6
6. `K6 = 2τ / (i6_1 − i6_2)`（正反差分消摩擦）
7. 换 2~3 个质量各做一次，看 K6 是否一致

**关键**：力臂要用钢尺量到毫米，且**重物必须挂在杆端**（不是轴附近）——
这正是前两次标定共同的坑。

**收益**：给 K6 一个和传感器无关的独立值。若独立测出 0.38~0.40，则整个体系闭环可信。

## P0-2　传感器只验证了**单点**（0.59 N·m）

**问题**：本次挂重只做了「500g × 120mm = 0.5884 N·m」一个点。得出 k=0.001，
但这只证明**在该点附近**准确。仪表放大器在大量程处可能非线性。

**风险量化**：如果 5 N·m 处偏 5%，在 0.6 N·m 处完全看不出来。

**怎么改**：用现有装置做 4 点：0.29 / 0.59 / 1.18 / 2.35 N·m
（力臂 120mm 固定，质量 250g / 500g / 1kg / 2kg），或力臂加倍到 240mm。
看读数是否严格 = m·g·L。现行 `torque485.py calib` 能自动拟合。

**收益**：确认 k 在全量程恒定，或发现非线性区间。

## P1-1　采样率不匹配，把相关性**压低了约 0.12**（已实测）

**问题**：臂侧 200 Hz（含 stick-slip 锯齿），传感器 50 Hz（平滑）。
逐点对比时高频噪声全算成「不相关」。

**实测证据**（对 `ALL_DATASET.csv` 做 5 点滑动平均）：

| 段 | 原始 r | 平滑后 r | 提升 |
|---|---|---|---|
| 一·拧紧 | +0.892 | +0.917 | +0.025 |
| 二·松开 | +0.531 | +0.570 | +0.039 |
| 松1 | +0.676 | +0.728 | +0.052 |
| **松2** | **+0.296** | **+0.493** | **+0.197** |
| 松3 | +0.723 | +0.891 | +0.168 |
| 紧1 | +0.788 | +0.924 | +0.136 |
| 紧2 | +0.304 | +0.365 | +0.061 |
| 紧3 | +0.828 | +0.891 | +0.063 |
| **平均** | **0.629** | **0.747** | **+0.118** |

**怎么改**：数据集统一提供 50 Hz 降采样版（或 5 点滑动平均版），
报告里同时给「原始 r」和「50 Hz r」。学术上更严谨。

**收益**：相关系数从 0.63 提到 0.75，且这是**真实信号**不是造假——
高频锯齿本就是电流法测不到的（stick-slip），物理上应当滤掉。

## P1-2　紧1 信噪比不足，应剔除或标注

**问题**：紧1 的传感器峰峰只有 **96 counts**（0.096 N·m），
而量化台阶 0.001 N·m，相对精度只有 1%；且臂侧峰值 0.13 vs 传感器 0.05，比值 2.47 明显异常。

**各段峰峰（counts）**：一·拧紧 240 / 二·松开 268 / 松1 245 / 松2 122 / 松3 178 /
**紧1 96** / 紧2 156 / 紧3 138

**怎么改**：紧1 从统计里剔除，或标注「信噪比不足，仅作参考」。
以后做实验时保证峰峰 ≥ 150 counts（0.15 N·m）。

## P2-1　实验三的对齐 OFF=−8.2s 是**互相关猜的**

**问题**：不是直接测量。三份 raw 分别给 −8.2 / −8.3 / −8.3，一致性不错，但仍是推断。

**怎么改**：采集时在 VM 侧写 `raw/<tag>.t0`（`time.time()`），
Windows 侧同时记 `t0_epoch`，差值就是精确偏移。
`SYNC_TEST.md` 里已有这套流程，本次没执行。

**收益**：对齐误差从 ±0.1s 降到 ±0.01s。

## P2-2　数据量偏少（每方向 3 段）

**问题**：松 3 段 + 紧 3 段，每方向只有 3 个样本，统计置信度有限。
松2 和紧2 的 r 只有 0.30（平滑后 0.49/0.37），很可能是单次偶然。

**怎么改**：每方向做到 5~8 段，看段间离散度。同时覆盖不同瓶盖松紧程度。

## P2-3　仪表量程利用率只有 3%，分辨率浪费

**问题**：量程 5 N·m = 5000 counts，但实验里最大只用 200 counts（0.2 N·m）。
量化台阶 0.001 N·m 对 0.16 N·m 的信号是 0.6%，还能接受；
但若把量程设成 1 N·m = 5000 counts，分辨率能提高 5 倍到 0.0002 N·m。

**风险**：仪表的 SH 标定改坏回不去（`CLR` 备份是厂家内部用）。
**建议**：不动仪表，改用**软件换算法**（如果仪表有更高分辨率的原始寄存器）。
需查手册确认 0x56 是否已是最高分辨率。

## P3-1　K6 是否真是常数？（分方向/分姿态）

**问题**：现在用单一 K6=0.3889 覆盖所有工况。但：
- 松方向反解 K=0.22，紧方向反解 0.39
- 差异部分来自弹开冲击（物理），但可能也有摩擦/姿态依赖

**怎么改**：分方向、分 J6 角度区间拟合，看 K6 是否系统性漂移。
若漂移 >10%，说明单常数不够。

---

## P3-2　Q6 与其他关节的系数关系仍没解释

**现状**：J2/J3 = 4.72、J4/J5 = 0.745、J6 = 0.389。
J6 比 J4/J5 还低一半，而 SDK 标称 J4~J6 是同一个值（0.958）。

**可能**：J6 有额外传动（同步带/齿轮）、或电流采样链路不同。
**怎么改**：查 piper 的 J6 传动结构，或对 J6 做电流采样标定（通已知电流看读数）。
