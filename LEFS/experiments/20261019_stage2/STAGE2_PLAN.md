## 2 起点比预想的好：K 已经有一个官方初值

读 `piper_sdk 0.6.1` 源码（`piper_msgs/msg_v2/feedback/arm_feedback_high_spd.py:84 cal_effort`）拿到一件此前没登记的事：

```
effort(0.001 N·m) = current_raw * coefficient
coefficient:  J1–J3 = 1.18125     J4–J6 = 0.95844
```

即 SDK 自己就把 `τ = K·I` 写死了，**只是给成两组常数、不分关节**：

| 关节 | K_SDK (N·m/A) | 依据 |
| --- | --- | --- |
| J1 / J2 / J3 | 1.18125 | 固定系数 |
| J4 / J5 / J6 | 0.95844 | 固定系数 |

三条要点：

1. **这是「核验起点」，不是校准证书**（指南 §5.1 原话）。K 是**有效系数**，包含减速比、效率与符号；厂家的两组常数在六个关节上不可能同时精确成立。
2. **`effort` 不携带独立信息** —— 它就是 `cur × 常数`。所以标定不能用 `effort` 去「验证」`cur`，那等于用同一个数验证自己。必须引入外部真值（砝码）。
3. 好消息：**量级与符号可以先用它做一次免费对照**，不用砝码就能判断「电流通道是否可信」，见 §4 的 S2-0。

> 这条同时印证了门 9「有条件闭合」的逻辑：静态差分里末端重力项被 K 吸收，末端质量只用于「K 量级是否合理」的旁证。现在这个旁证有了具体形式 —— 用臂**自身**的重力矩去比。

## 2.5 末端口径：定案「带夹爪」，以及为什么这 0.5 kg 必须算准

**定案（2026-10-19 17:58，用户）**：本次复现**带夹爪**。末端 = 标准两指夹爪（500 g）+ 标定工装。
重力模型默认 `--gripper urdf`，即 `end_mass = 0.500 kg`、质心按 URDF 算到 **37.6 mm**。

> 17:53 曾一度定案「不装夹爪」，4 分钟后改回。**最终配置以本节为准**；
> 两种口径工具都支持（`--gripper none` 复现裸臂），所以不会因为改主意而丢数据，
> 但负载预算与 S2-0 的姿态选择会变（见 S2-1、S2-0 两节）。

### ① URDF 里夹爪是真实存在的，不是占位

| 事实 | 数字 | 含义 |
| --- | --- | --- |
| URDF 全部 link 质量合计 | **4.66 kg** | 比官方本体 4.2 kg 多 0.46 kg |
| 其中 `gripper_base` + `link7` + `link8` | **0.45 + 0.025×2 = 0.50 kg** | URDF 是「臂 + 夹爪」完整模型 |
| 4.66 − 0.50 | **4.16 kg ≈ 本体 4.2 kg** | 交叉验证成立 |

注意这三件的 `<mass` 在 URDF 里是**跨行**写的（`<mass\n value=...`），用单行正则扫会全部漏掉，
从而误判「URDF 不含夹爪」。这个坑已经踩过一次，别再踩。

### ② 夹爪质心不在法兰原点，而在工具轴上 37.6 mm

| 件 | 质量 | 质心（相对法兰） |
| --- | --- | --- |
| `gripper_base` | 450 g（占 90%） | 沿工具轴 **32.1 mm** |
| `link7` / `link8`（两指） | 各 25 g | y = **±9.7 mm**，左右**对称抵消** |
| **组合质心** | **500 g** | **(0, 0, 37.6) mm**，横向净偏移 < 0.2 mm |

所以不能把它当「原点上的 0.5 kg」——那会低估力臂。已固化为自测 T11c（`selftest` 18/18）。

### ③ 这 0.5 kg 会改符号，也会把一个假的「量纲 bug」造出来

| 姿态 / 关节 | 裸臂 | **带夹爪（现场）** | 变化 |
| --- | --- | --- | --- |
| P1 · J2 | +1.155 | **+2.000** | +73% |
| P1 · J3 | −2.575 | **−0.884** | 只剩 1/3（−66%） |
| P1 · J5 | −0.216 | **+0.356** | **反号** |
| P2 · J2 | −1.652 | −0.393 | 只剩 1/4 |

最危险的一条是 **P1 的 J3**：若口径少算夹爪，预测力矩只有真实值的 1/3，
反推的隐含 K 就会偏小近 **3 倍**，直接越过 S2-0 的 0.5~2.0 倍判据，
表现成一个**假的「电流量纲读错」**。口径错不会只是"数值偏一点"。
这正是本节存在的理由，也是 `sweep`/`check` 报告**首行必须打印口径**的原因。

## 3 离线结论：哪些关节根本标不出来

`stage2_design.py sweep` 用 URDF（`piper_description.urdf` 的质量与质心）算 `Δτ = Jᵀ·wrench`，
载荷 **0.5 kg**（带夹爪后的实际可用档，见 S2-1）、法兰外伸 50 mm、偏心横杆 80 mm、横向拉力 10 N。
完整表在 `DESIGN_SWEEP.md`，摘要如下：

| 关节 | 竖直砝码 0.5 kg 的 Δτ（代表性姿态） | 判据 | 结论 |
| --- | --- | --- | --- |
| **J1** | **+0.00**（所有姿态） | 重力与 J1 轴平行 ⇒ 力臂为 0 | **必须横向拉**：10 N 切向给 **0.17~2.74 N·m，随姿态差 15 倍**（P8 2.74 / P1 1.50 / P4 仅 0.17） |
| J2 | P1 +0.73 / P2 +0.95 / **P8 +1.27** | 力臂最长，最好标 | 砝码 |
| J3 | P1 +1.58 / P4 −0.34 | 正负两个方向都有 | 砝码，且天然覆盖双向 |
| **J4** | P1 0.00 / **P6 −0.64** | 质心落在 J4 轴线上时为 0 | 砝码 **但 J4 必须转开**（≥60°） |
| J5 | P1 +0.46 / P4 **−0.77** | 双臂长、双向 | 砝码 |
| **J6** | P1 0.00 / **P7 −0.36** | 质心落在工具轴（= J6 转轴）上时为 0 | 砝码 **+ 偏心横杆 + J6 转开 90°** |

**降档不损失覆盖**：从 1.0 kg 降到 0.5 kg 后，六个关节的可辨识性（判据 |ΔI| ≥ 20 counts）
**一个都没丢** —— 最弱的 J6 在 P7 仍有 371 counts，是判据的 18 倍。这是敢用单档的原因。

两条几何事实需要记住（已固化成自测 T9a–T9d）：

- **纯轴向载荷对 J6 恒无矩**，换姿态也一样 —— 因为 J6 的转轴就是工具轴，质心在轴上时力臂恒 0。
- **加了横杆还不够**：横杆若落在「轴与重力张成的竖直平面」内，力矩仍是 0（T9c，P1 下 0.000 N·m）；
  必须靠 J6 自转把偏心质量转到该平面之外（T9d，P7 下 −0.711 N·m）。

同理 J1：**顺着臂拉（径向）对 J1 的力臂恰好为 0**，必须拉切向（T6a/T6b）。
这不是「力矩小一点」的问题，是 0 与 1.5 N·m 的区别 —— 拿径向拉力去标 J1，会得到一条 Δτ=0 但 ΔI≠0 的直线，
拟合出来的 K 是「摩擦/零点/K」的混合物，而且残差看起来还挺小。

**因此工装清单比指南的设想多两件**：滑轮（或弹簧测力计）+ 偏心横杆。

**顺带一个容易白掉一个数量级的点**：同一关节在不同姿态下的力臂能差 15 倍（J1 在 P8 是 2.74 N·m，在 P4 只有 0.17）。
`DESIGN_SWEEP.md` §5 的最后一行给了每个关节的**最强姿态**，标定时优先用它们：

```
J1→P8(拉力 2.74) J2→P8(砝码 1.27) J3→P8(砝码 1.80)
J4→P4(拉力 1.62) J5→P8(拉力 1.32) J6→P5(拉力 0.80)
```

## 4 六步施工（S2-A 前置工具 + S2-0~S2-4；每步都写清：为什么 / 在哪台机器 / 判据）

### S2-A 前置工具：`stage1_cmd.py` 加 `pose` 子命令（本机改，VM 跑）

**为什么**：姿态矩阵要求「停在指定六轴角度」。现在只有 `hold`（保持当前姿态）、`sine`、`step`（相对偏移），
没有一个「慢速走到绝对目标角并停住」的模式。没有它，§5 的「换至少 5 个姿态」只能靠人手拖 + 再切 CAN_CTRL，
而人手拖会产生外力、位置也不可复现。

**接口**（保持 2.0 的自建 socket、逐帧判成败、失败不写 CSV 的骨架）：

```
python stage1_cmd.py pose --iface can0 --target-deg 0,45,-60,0,45,0 \
       --rate-deg-s 8 --hold-s 30 --out cmd/p1_load
```

**必须有的守卫**（缺一条就不许跑）：

1. `--target-deg` 六个数缺一不可；每轴对 `固件∩URDF` 包络检查，越界**直接拒跑**（不做限幅后照发）。
2. 起步前读当前 q，计算最大单轴行程；按 `--rate-deg-s` 折算理论时长并在终端回显，让人能预判。
3. 每拍仍走 `clamp_step`，但限幅值 = `rate × dt`，不是拍脑袋常数。
4. 到达后**不是靠时间到了就算到**，而是 `|q - q_target| < 0.5°` 连续 20 拍才转 `hold` 段；否则报 `未到位` 并以非零退出码结束。
5. 发送失败仍然：不写 CSV、不推进 `q_prev`、连续 30 拍 ABORT（沿用 2.0 的规则，别退化）。

**判据**：`selftest` 新增两条 —— `F_pose_limits`（越界目标被拒）、`G_pose_unreached`（注入「卡住」的假 socket，必须报未到位）。

**状态**：✅ **2026-10-20 完成**。`stage1_cmd.py` 3.0（`pose` + `selftest`），
本机与 VM 上 `selftest` 均 **16/16 通过**；VM 上 dry-run（带真实 `joint_limits.json`）产物齐全，
越界目标退出码 **2**、无任何帧下发。

落地时比原设计多了两条，都是实测逼出来的：

| 增补 | 原因 |
| --- | --- |
| `--limit-tol-deg`（默认 3.0，包络向外放宽） | 实测自然零位 **J2=−2.003°、J3=+1.798°** 越过固件标称边界。不放宽的话 `hold` 第一拍就被限位夹紧把臂从 −2° 拽到 0° —— **限幅自己造出一次没人下达的移动**。 |
| `--settle-s`（默认 2 s）/ `--arrive-cycles`（默认 20） | 到位判定只看**实测 q**，不看指令；到不了就退 **3**（未到位）、连续 30 拍发不出去退 **4**（ABORT）。 |
| `--allow-outside-limits` | 越界只提供「显式认账」的口子，默认拒跑（退出码 2），不做「限幅后照发」。 |

### S2-0 空载静态对照（不需要任何硬件，先跑这个）

**为什么**：在三件事上一次拿全 —— ① 隐含 K 是否落在 SDK 系数附近（量级对不对）；② 电流噪声底 σ（决定 ΔI 至少要多大才算信号）；③ 符号是否自洽。这三条任何一条不成立，后面装砝码都是在错的前提上做精工。

> 原 P4 = `(0,100,−20,0,60,0)` 只按力矩可辨识性挑，没做几何检查。URDF 正解算出来
> **TCP z = 67 mm、离立柱净空 −28 mm** —— 夹爪正好弯进基座立柱。实跑时臂弯下去卡在底盘上，
> 而脚本当时还在按时间推进指令，等于**持续往障碍里推**。
>
> 三处修正：
> 1. **P4 换成 `(0,100,−75,0,60,0)`**：净空 +244 mm、TCP z=203 mm，
>    J2 自重力矩 **−2.60 N·m**（P1 是 +2.00），反号判据仍然成立且更干净。
>    J5 不再反号（+0.07），符号判据只留 J2 —— 一次验一个轴，够用。

变化量不到 20%，噪声和姿态误差会把"反号"淹掉；P4 是 −2.11，量级与 P1 对称，判起来干净。
顺带 J5 在 P1/P4 也反号，一次能验两个轴。

也就是说 **不需要砝码**就能造出「正 τ / 负 τ」两组观测，比指南 §4.2 坑二要求的
「正反方向运动 + 受控加载」更省事，也不引入摩擦方向变化。

**注意区分两张表**：这里是**臂自身重量**的力矩（`DESIGN_SWEEP.md` §4，带夹爪口径，
随姿态换号）；§3 那张是**载荷 0.5 kg** 的 Δτ（`DESIGN_SWEEP.md` §1，恒为正）。
两边的数字不能互相代入。

### S2-1 工装与称重（硬件，含一个**零返工窗口**）

**为什么先称重**：阶段 2 一开始末端配置就冻结；门 9 的实测总重也是在这里一次补齐（`GATE9_END_EFFECTOR.md` 的关闭路径）。

**清单**：

| 件 | 规格 | 用途 | 备注 |
| --- | --- | --- | --- |
| 砝码 | **0.5 kg** 一个（若秤准，可另备 0.8 kg 作大信号档） | 两档差分 | **1.0 kg 不能用**——带夹爪后总负载会超 1.5 kg，见下方预算 |
| 挂钩 + 细绳 | 绳长 ≥ 0.5 m，直径 ≤ 2 mm | 竖直悬挂，绳要垂直、不蹭臂 | 绳**不垂直**会引入横向分量，Δτ 直接算错 |
| 偏心横杆 | 80 mm，孔位对法兰 | 标 J4/J6 | 本轮唯一需要加工的件 |
| 滑轮 / 定滑轮夹 | 可夹在桌面或立柱 | 给 J1 施切向水平力 | 必须能对准**切向**，不是顺着臂 |
| 弹簧测力计 | 0~50 N | 读滑轮实际拉力（比砝码更灵活） | 有它就可以不用砝码调力值 |
| 电子秤 | 分辨率 ≤ 5 g | 称砝码**实测**质量、称末端总重 | 砝码标称值不许直接当质量用 |
| 卷尺/卡尺 | — | 量悬挂点到各关节轴的实际力臂 | 设计值只是量级，力臂必须实测 |

**同时要做（门 9 关闭）**：称**带夹爪的末端总重**（夹爪 + 转接板 + 横杆 + 线缆），


**⚠️ 负载预算（按「带夹爪」重算）**：本体负载 1.5 kg 是**含末端工具**的总量。

| 项 | 质量 | 说明 |
| --- | --- | --- |
| 标准两指夹爪 | **0.50 kg** | 额定值，实测覆盖 |
| 法兰转接板 + 横杆 + 挂钩/绳 | ≈ 0.1 kg | 加工与装配件，称了再填 |
| 砝码 | **0.50 kg** | 静态悬挂，**可带载慢速运动** |
| **合计** | **≈ 1.10 kg** | 在 1.5 kg 限内，**余量约 0.4 kg** |
| （若改用 1.0 kg 砝码） | ≈ 1.60 kg | ❌ **超载** —— 这就是不能用 1.0 kg 的原因 |

⇒ **主力档就是 0.5 kg 单档**。想要"大信号"最多加到 0.8 kg（合计 1.4 kg，余量只剩 0.1 kg，不建议）。

**降档不损失标定能力**：§3 已核对，0.5 kg 下六个关节的可辨识性一个都没丢
（最弱的 J6 在 P7 仍有 371 counts，判据的 18 倍）。**不要为了"信号大"去冒超载的险。**

**两件容易忽略的事**：

1. **称重前先看夹爪是否通电会自检**。若它上电时两指会张合，静态采集会被它自己搅乱。
   建议：机械上保留（质量就在那里、与 L0 数据同配置），**电气上断开 CAN 或断电**，
   让它退化成一块纯被动质量。这也顺便解释了 `0x2A8` 那 15000 帧全 0 —— 它本来就没被总线识别。
2. **夹爪 ≠ 复现对象**。本复现仍然不驱动、不采集、不验收夹爪，它只是末端质量的一部分；
   第 7 轴不参与任何判据。

**这一步必须在 S2-2 第一次采集之前做完并定案**，之后不许再动末端。

### 单档砝码怎么还能拟合？—— 用姿态和角度做「几何变载」

1.0 kg 档被负载预算否掉了（S2-1），于是只剩 0.5 kg 一个质量档。这本来是个问题：
**拟合 `Δτ = K·ΔI + b` 需要多个不同 Δτ 的工作点**，只有一个载荷档，难道只能得一条过原点的直线？

不需要第二档砝码，因为 Δτ 不只是载荷的函数，它还是**姿态**和**角度**的函数：

| 关节 | 0.5 kg 在不同姿态下的 Δτ（N·m） | 动态范围 |
| --- | --- | --- |
| J2 | P1 +0.73 / P2 +0.95 / P8 +1.27 | 1.7× |
| J3 | P4 −0.34 / P2 +1.12 / P1 +1.58 / P8 +1.80 | **5.3×，跨零** |
| J5 | P4 −0.77 / P1 +0.46 / P5 +0.72 | **跨零** |
| **J6** | P9 −0.18 / P10 −0.31 / P6 −0.34 / P7 −0.36 | 2.0× |

**J6 的力矩严格按 sin(q6) 走**（实测：30°→178、45°→251、60°→308、90°→356 counts）。
也就是说，**同一个砝码，转一下 J6 就换一个载荷档**。P9/P10 两个姿态就是为此加的，
代价只是多走两次位，比再买一个砝码便宜得多。

唯一需要 honest 的地方：这些点**共用同一个质量真值**，所以它们验证的是
「K 与截距的线性」，而不是「质量标定的准确性」。质量真值由电子秤保证（S2-1 清单里已列）。

**预计点数**：姿态 10 × 平均 3 次采（空 / 载 / 卸载复测）+ J1 双向 4 次 ≈ **34 个采集点，约 50 分钟**（含走位）。

### S2-3 拟合（本机，纯离线）

**为什么单独写工具**：指南 §5.3 的「保留截距项、检查残差」，逐点相除再平均会把这个信息抹掉 —— 而截距恰恰是摩擦与零点的直接读数。

要写的 `stage2_fit.py`（接口先定死，实现放下一步）：

```
python stage2_fit.py --calib calib/ --out calibration/
```

- 每个关节独立做 `Δτ_ref = K·ΔI + b` 的加权最小二乘（**截距 b 必须留着并单独报告**）；
- 输入不是「一次采集」，而是「空载 − 加载」配对后的 ΔI；配对按姿态标签，不按时间相邻；
- 残差、`R²`、残差是否随 |Δτ| 系统性弯曲（弯曲 = 模型不对，通常是摩擦没建模）；
- **独立验证**：留一个姿态（P3）完全不参与拟合，用它算验证误差，写进 `k_table.json → holdout_error`；
- 回差 = 同一 |Δτ| 下「加载 − 卸载」的 ΔI 之差，按关节报中位数与最大值；
- 未达可辨识判据的关节写 `state: 未标定`，`K: null`（**不许填 K_SDK 冒充结果**，这正是指南 §2.3 说的「伪精确比空白更危险」）。

## 5 三条红线怎么落进流程（指南 §5.4）

| 红线 | 在本方案里的具体防线 |
| --- | --- |
| 不用 MIT 的 `T_ref` 当力矩真值 | 本方案**全程不用 MIT 模式**；真值只有「砝码质量 × 实测力臂 × 重力」和「滑轮拉力 × 实测力臂」 |

## 6 预判的失败模式（每条都对应一次可能白跑）

| 现象 | 真因（大概率） | 处置 |
| --- | --- | --- |
| 某关节 ΔI 很小但残差也小 | 该关节**根本没被激励**（本方案已用 sweep 提前排除，但工装装错方向会复现） | 回到 `sweep` 对照该姿态的 Δτ，不要调拟合 |
| J1 的 K 明显偏大 | 用**径向**拉了（力臂 0，测到的是摩擦） | 改切向；用 `sweep` 的 J1 行核对 Δτ |
| J6 的 K 离散度极大 | 横杆方位随姿态变化，不同点实际力臂不同 | 每个姿态单独量力臂，别用同一个设计值 |
| 加载与卸载差很多 | 回差（摩擦），**不是**测量错误 | 如实报回差；不要用平均抹平 |
| `cur` 长时间恒定不变 | 采到了 `0x261~0x266` 的母线电流（1.5 kg 机型恒 0） | 换 `0x251~0x256`；`parse` 的 `cur` 已只取高速帧，但要核对 |
| 同一姿态两次采差别 > 10% | 温度漂移或没停稳 | 延长等待；记录温度；阶段 3 前把预热写成固定 5 min+ |
